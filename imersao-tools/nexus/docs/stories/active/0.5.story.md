# Story 0.5 — Proxy Anthropic Edge runtime `/api/anthropic/proxy` com SSE streaming

**Story ID:** 0.5
**Epic:** 0 — Migração Estrutural
**Status:** Ready for Review
**Bloqueia:** **EPIC 1 COMPLETO** (sem proxy seguro, cérebro multi-intent não arranca)
**Bloqueada por:** 0.1 (estrutura v2 tem de existir)

---

## User Story

Como Eurico, quero que todas as chamadas à Anthropic API passem por um proxy server-side no Edge runtime, para que a minha API key nunca apareça no bundle do browser nem em qualquer ficheiro do cliente.

---

## Acceptance Criteria

- **AC1:** `app/api/anthropic/proxy/route.ts` existe com `export const runtime = 'edge'` e aceita `POST` com body `{ messages, model, stream?, max_tokens?, tools? }`.
- **AC2:** Handler lê `ANTHROPIC_API_KEY` de `process.env` (server-side), nunca exposta ao cliente. Se key ausente, retorna `{ error: 'API key não configurada' }` com status 500.
- **AC3:** Quando `stream: true`, o handler devolve SSE stream (`Content-Type: text/event-stream`) com eventos `data: {type, content}` conforme Anthropic streaming protocol.
- **AC4:** Quando `stream: false`, o handler devolve JSON com a resposta completa.
- **AC5:** Rate limiting via Vercel KV: máximo 60 req/min por IP (sliding window conforme `architecture-v2.md §9.3`). Responde 429 com header `Retry-After: 60` quando limite atingido.
- **AC6:** Middleware de autenticação: rota `/api/anthropic/proxy` verifica cookie de sessão (placeholder — verificação real em Story 0.6). Se cookie ausente, retorna 401.
- **AC7:** Verificável: executar `npm run build` e confirmar que `ANTHROPIC_API_KEY` NÃO aparece no bundle client (verificar output de `next build --analyze` ou grep no `.next/static/`).
- **AC8:** Vitest unit test com MSW mock verifica que proxy encaminha correctamente e que a key nunca vaza para response headers ou body.

## Dev Notes

- **Runtime:** ADR-1 — `export const runtime = 'edge'` para proxy Anthropic (latência baixa, pass-through)
- **Anthropic headers obrigatórios:** `anthropic-version: 2023-06-01`, `content-type: application/json`, `x-api-key: process.env.ANTHROPIC_API_KEY`
- **SSE protocol Anthropic:** ver `architecture-v2.md §8` — eventos `meta`, `tool_start`, `tool_complete`, `text_delta`, `done`; usar `TransformStream` ou `ReadableStream` do Edge runtime
- **Rate limiting:** `architecture-v2.md §9.3` — "KV INCR + EXPIRE; 60 req/min por IP; Resposta 429 com header Retry-After"
- **MSW mock:** `architecture-v2.md §5.2` — snippet exacto para handler Anthropic multi-intent; copiar para `tests/mocks/handlers/anthropic.ts`
- **Segurança crítica:** PRD NFR5 — "API key Anthropic exclusivamente em Vercel env, NUNCA no client". Verificar com bundle analyzer ou grep após build.
- **Sessão placeholder:** Cookie check simples para já — Story 0.6 implementa bcrypt + KV real. Nota no código: `// TODO: auth real em Story 0.6`
- **Vercel KV:** `architecture-v2.md §9.2` — usar `@vercel/kv` para rate limiting. Em dev local, KV pode falhar graciosamente (sem rate limit em localhost).
- **ESTA STORY É BLOQUEANTE PARA EPIC 1** — sem proxy seguro, `@dev` não pode começar Story 1.1. Prioridade máxima após 0.1.

## Anti-padrões (explícitos para esta story)

- **NÃO** expor `ANTHROPIC_API_KEY` em nenhum ficheiro client-side
- **NÃO** usar `NEXT_PUBLIC_ANTHROPIC_API_KEY` — a key é server-only (NFR5)
- **NÃO** chamar `https://api.anthropic.com` directamente do browser — toda a comunicação passa por este proxy
- **NÃO** usar Node runtime neste endpoint — deve ser Edge para latência mínima (ADR-1)
- **NÃO** remover rate limiting — é requisito de segurança (NFR9, arch §9.3)
