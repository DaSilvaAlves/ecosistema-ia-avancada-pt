## Nota do `@sm` River

### Contexto do escopo

A Story 3.1 entregou `lib/db/repos/categories.ts` com CRUD completo + `createCategory` que **rejeita duplicados case-insensitive** e `listDefaultCategories()`. A Story 3.2 limita-se a semear as 10 categorias default PT nessa tabela — em nenhum caso recria repositórios ou schemas já existentes.

A semeadura deve ser **idempotente**: se executada num browser onde as categorias já existem (ex: utilizador que já usou a app), não deve falhar nem duplicar. O `createCategory` existente da Story 3.1 já rejeita duplicados (lança `Error`), mas o seed deve capturar silenciosamente essa rejeição para cada categoria individualmente — permitindo execução parcial sem abortar.

[AUTO-DECISION] A1 — "onde e quando executar o seed": A Story 3.1 Dev Notes (L252) já antecipou: "a Story 3.2 semeia as 10 defaults via `db.categories.bulkAdd`". O ponto de activação mais adequado é um hook de inicialização da aplicação (on-mount, one-shot — padrão da Story 2.7 `runRecurrenceEngine`). Alternativa: função `seedDefaultCategories()` chamada explicitamente na inicialização. Decisão firme: função explícita `seedDefaultCategories()` em `lib/financas/seedCategories.ts`, chamada no inicializador da app (ex: `app/layout.tsx` ou hook `useFinancasInit`). Esta abordagem é testável de forma isolada (precedente: `runRecurrenceEngine` é função pura, não hook) e reutilizável por testes.

## User Story

### Padrão de idempotência a seguir

`createCategory` (Story 3.1, `repos/categories.ts`) lança `Error('Já existe uma categoria com o nome "X"')` em duplicados. O seed captura por item:

```typescript
export async function seedDefaultCategories(): Promise<void> {
  for (const cat of DEFAULT_CATEGORIES) {
    try {
      await createCategory({ ...cat, isDefault: true });
    } catch {
      // categoria já existe — idempotente, ignorar silenciosamente
    }
  }
}
```

**Atenção:** capturar _qualquer_ erro silenciosamente pode mascarar problemas reais (ex: falha de IndexedDB). Alternativa mais robusta: capturar apenas o `Error` de duplicado (verificando a mensagem ou usando um erro tipado). `@dev` pode decidir com base no padrão dos repos existentes — se `createCategory` não usa erros tipados, capturar genericamente é aceitável para MVP.

### Ponto de inicialização — padrão Story 2.7

A Story 2.7 usa o mecanismo `ADR-2.7-1` (activação via `useEffect` one-shot on-mount). Verificar o ficheiro onde `runRecurrenceEngine` é chamado — a `useFinancasInit` deve seguir o mesmo padrão:

```typescript
// hooks/useFinancasInit.ts
import { useEffect } from 'react';
import { seedDefaultCategories } from '@/lib/financas/seedCategories';

export function useFinancasInit(): void {
  useEffect(() => {
    void seedDefaultCategories().catch((err) => {
      console.error('[useFinancasInit] seed failed:', err);
    });
  }, []);
}
```

O hook `useFinancasInit` é chamado no componente raiz (layout ou provider) para garantir execução one-shot por sessão.

### Chave primária `name` — comportamento esperado

A `categories` tabela usa `name` como PK (`categories: 'name, isDefault'`). A `createCategory` internamente faz `db.categories.add(data)` — se o `name` já existe, o Dexie lança `ConstraintError`. O `createCategory` captura esse erro e lança o `Error` PT-PT de duplicado. O seed captura o `Error` PT-PT. Cadeia correcta: IndexedDB → Dexie → `createCategory` → `seedDefaultCategories`.
