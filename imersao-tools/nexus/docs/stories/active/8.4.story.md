### DESIGN-DECISION D-8.4-SIBLING — Proxy sibling por provider; Anthropic intocado

**Pergunta:** Como introduzir o caminho client OpenAI sem tocar no caminho Anthropic existente (e nos ~2400 testes que o cobrem)?

**Decisão:** ADR-10 §3.3 Abordagem B (sibling proxy) — criar `/api/openai/proxy/route.ts` como irmão independente de `/api/anthropic/proxy/route.ts`. Os dois proxies têm upstream URL **constante** (hardcoded), auth scheme **próprio** (`Authorization: Bearer` para OpenAI vs `x-api-key` para Anthropic), e chave rate-limit **separada** (`nexus:ratelimit:openai:*` vs `nexus:ratelimit:anthropic:*`). O `InferenceTransport` Anthropic e `/api/anthropic/proxy` ficam byte-a-byte intocados.

**Justificação:** ADR-10 §3.3 cita explicitamente a Abordagem A (proxy normalizador genérico) como "rejeitada" porque "move a reagregação de `tool_calls` e a tradução de wire para o Edge e **reescreve o caminho Anthropic** → superfície de regressão directa sobre os testes de fidelidade duramente conquistados". A duplicação de ~40 linhas de boilerplate (auth + rate-limit) é dívida aceitável (`REC-ADR10-PROXY-DRY` — extracção futura após ambos os proxies estáveis).

**Alternativa rejeitada:** Abordagem A (proxy normalizador). Razão: viola ADR-10 §3.3 explicitamente; introduz regressão sobre caminho Anthropic; sobrepõe dois concerns num único proxy Edge.

### DESIGN-DECISION D-8.4-BROWSER-SAFE — `openai-inference-transport.ts` não importa o SDK `openai`

**Pergunta:** O `toOpenAIMessages` que o `OpenAIExecutor` (server-side) usa vive em `lib/agent/providers/openai.ts`. Pode o `OpenAIInferenceTransport` (client-side) importá-lo de lá?

**Decisão:** NÃO. `lib/agent/providers/openai.ts:1` tem `import OpenAI from 'openai'` — o SDK inteiro seria incluído no bundle client se o ficheiro fosse importado de `'use client'`. O `openai-inference-transport.ts` define `toOpenAIMessages` **localmente** (sem importar o SDK), espelhando a função de `openai.ts:259-330` e documentando o cross-reference num comentário. Este é exactamente o padrão que `InferenceTransport` já usa: `toAnthropicMessages` é local (`inference-transport.ts:99-124`) e não importa `@anthropic-ai/sdk`. Similarmente, `proxyErrorMessage` e `OpenAITransportStreamErrorAlreadyEmitted` são locais.

**Imports seguros para `openai-inference-transport.ts`:**
- `@/lib/agent/schemas` (`ClassificationResultSchema`, `LLMStreamEventSchema`)
- `@/lib/agent/providers/types` (interfaces, type-only)
- `@/lib/agent/tools/registry` (`toolsToOpenAIShape` — browser-safe)
- `@/lib/agent/sse-lines` (`iterateSseData` — nova extracção)
- `@/lib/agent/models` (`DEFAULT_OPENAI_CLASSIFIER_MODEL`, `DEFAULT_OPENAI_EXECUTOR_MODEL` — re-exported por `openai.ts:53-58` ou importados directamente de `models.ts`)
- `@/lib/agent/prompts/executor-system` (`EXECUTOR_SYSTEM_PROMPT`)
- `@/lib/agent/classifier-json` (`stripJsonMarkdownFences`)

**NÃO importar:** `openai` (SDK), `@/lib/agent/providers/openai` (puxaria SDK), `@anthropic-ai/sdk`.

### DESIGN-DECISION D-8.4-SSE-LINES — Extracção de `iterateSseData` para `sse-lines.ts` como refactor zero-comportamento

**Pergunta:** A `iterateSseData` existe em `inference-transport.ts:137-177`. Como partilhá-la com `openai-inference-transport.ts` sem modificar o comportamento do caminho Anthropic?

**Decisão:** Criar `lib/agent/sse-lines.ts` com a função `iterateSseData` exportada (conteúdo idêntico a `inference-transport.ts:137-177`). Modificar `inference-transport.ts` para importar de `sse-lines.ts` em vez de definir localmente — refactor puro, sem mudança de comportamento. Os testes de `InferenceTransport` existentes continuam a passar por construção (o comportamento é byte-a-byte idêntico). Esta é a "Nota DRY de baixo risco" do ADR-10 §3.3 citada acima.

### DESIGN-DECISION D-8.4-CLIENT-SELECT — Selecção de transport em `client-executor.ts` por `NEXT_PUBLIC_LLM_PROVIDER`

**Pergunta:** Como modificar `client-executor.ts` para seleccionar `OpenAIInferenceTransport` vs `InferenceTransport` sem quebrar os testes existentes que injectam transport via argumento?

**Decisão:** O `runClientAgent` lê `process.env.NEXT_PUBLIC_LLM_PROVIDER` (inlined pelo Next.js no bundle client em build time) no corpo da função (não como default de parâmetro) apenas quando o argumento `transport` não é fornecido explicitamente. O argumento `transport` mantém prioridade absoluta — testes que passam um mock continuam a funcionar sem alteração. O tipo do parâmetro `transport` passa de `InferenceTransport` para a intersecção `ClassifierProvider & ExecutorProvider` (ambas as classes implementam ambas as interfaces), tornando-o agnóstico ao provider concreto.

**Risco:** `process.env.NEXT_PUBLIC_LLM_PROVIDER` é inlined em build-time pelo Next.js — logo a selecção é determinística por build, não por request. Está correcto: o provider é uma decisão de deployment, não de runtime por-utilizador.

### Análise de ciclo de vida de estado — `internal-state-contract-gate.md` (obrigatória — caminho QUENTE)

> Identificação prévia ao `@dev *develop`, conforme `internal-state-contract-gate.md`. A 8.4 distribui estado por ≥2 camadas (browser client + proxy Edge + SSE wire). Risco alto: padrão dos 4 Major da Story 4.9.

**Eixo (a) — Classes de estado por camada:**

| Camada | Estado | Notas |
|--------|--------|-------|
| `OpenAIInferenceTransport` (browser) | `Map<index,{id,name,argsAccumulator}>` para `tool_calls`; `inputTokens`/`outputTokens` (contadores); `res.body` ReadableStream (aberto/fechado); sentinel `OpenAITransportStreamErrorAlreadyEmitted` | Accumulator por `index` (não por `id`) — obrigatório porque chunks de continuação não trazem `id` |
| `/api/openai/proxy` (Edge) | Stateless por design; estado transitório: resultado de `getSession` (válido/inválido), counter KV de rate-limit, `upstreamResp.body` (passado através como ReadableStream) | Proxy não acumula state entre requests |
| SSE wire OpenAI | `choices[0].delta.tool_calls[{index,id,function:{name,arguments_fragment}}]`; `choices[0].delta.content` (texto); `usage` (só com `stream_options:{include_usage:true}`, no chunk final); `data: [DONE]` | `id` e `function.name` chegam APENAS no 1.º chunk de cada `index`; chunks seguintes trazem só `arguments` |

**Eixo (b) — Transição já ocorrida (round-trip crítico):**

`id` do stream → armazenado em `Map[index].id` → emitido como `tool_use.id` → consumido pelo `toolCallingLoop` (`executor.ts`, intocado) → re-injectado como `LLMMessage{role:'tool', toolCallId: id}` → passado para `toOpenAIMessages` local → `{ role:'tool', tool_call_id: id }` no body OpenAI → **OpenAI rejeita** se `tool_call_id` não corresponder ao `tool_calls[].id` da mensagem `assistant` anterior.

Garantia a verificar: o `id` emitido no `tool_use` é **exactamente** o `id` que chegou no 1.º chunk do `index` correspondente (não construído, não truncado). O cenário multi-tool (≥2 `index`) prova que o Map não mistura `id` de indexes diferentes.

**Eixo (c) — Caminhos de falha previstos:**

| # | Falha | Resposta esperada |
|---|-------|-------------------|
| F1 | Rede — `fetchFn` lança (DNS/CORS/timeout) | Capturado pelo outer try-catch de `execute()`; emite `error` LLMStreamEvent + relança |
| F2 | Auth expirada — proxy retorna 401 | `!res.ok` no transport → throw `Error` PT-PT com status 401 e detalhe |
| F3 | Rate limit — proxy retorna 429 | `!res.ok` → throw `Error` PT-PT com status 429 e `Retry-After` |
| F4 | Upstream OpenAI falha — proxy retorna 502 | `!res.ok` → throw `Error` PT-PT com status 502 |
| F5 | Stream abortado antes de `[DONE]` | `iterateSseData` termina o loop; `done` emitido com tokens acumulados até ao momento (fail-safe, não crash); tool calls incompletos em Map descartados |
| F6 | `JSON.parse` de accumulator inválido (args fragmentados malformados) | `parsedInput = JSON.parse(argsAccumulator)` lança → emite `error` LLMStreamEvent + throw `OpenAITransportStreamErrorAlreadyEmitted` |
| F7 | `res.body` ausente (resposta sem corpo) | throw `Error` PT-PT "proxy não devolveu corpo de stream" |
| F8 | Mismatch de flags (`NEXT_PUBLIC_LLM_PROVIDER=openai`, `LLM_PROVIDER=anthropic`) | Client usa OpenAI proxy; server (factory) usa Anthropic. Caminho client independente do factory — `assertProviderFlagsAgree()` (factory) captura em runtime server. O proxy em si funciona (recebe body OpenAI, reencaminha para OpenAI). Fail-visible (ADR-10 §3.4). |

## Story

**As a** utilizador do Nexus v2 com `NEXT_PUBLIC_LLM_PROVIDER=openai`,
**I want** o browser a comunicar com o cérebro através de um proxy Edge OpenAI dedicado e um transport client-side fiel ao wire SSE da OpenAI,

## Acceptance Criteria

> Cada AC traça a ADR-10 §8 row S4 e a código real verificado em `main`. Constitution Artigo IV (No Invention).

**AC1 — Proxy OpenAI Edge (`app/api/openai/proxy/route.ts`)**
- `export const runtime = 'edge'`
- Auth via `getSession(req)` — retorna 401 `{ error: 'Não autenticado.' }` se `!session.valid` (espelho `anthropic/proxy/route.ts:89-93`)
- Rate-limit KV sliding window por IP, chave `nexus:ratelimit:openai:${ip}:${minute}` (distinta da Anthropic — `nexus:ratelimit:anthropic:*`), 60 req/min, 429 se excedido, fail-open sem KV
- Upstream URL CONSTANTE hardcoded: `const OPENAI_URL = 'https://api.openai.com/v1/chat/completions'` — o proxy NÃO aceita nem usa um URL do body do request (sem SSRF)
- `OPENAI_API_KEY` lida de `process.env.OPENAI_API_KEY` server-side; retorna 500 se ausente; nunca logada; nunca no bundle client
- Header de auth para upstream: `Authorization: Bearer ${apiKey}` (OpenAI); NÃO `x-api-key` (Anthropic); NÃO `anthropic-version`
- Body validation mínima: `messages` (array) + `model` (string) obrigatórios; 400 se ausentes
- Streaming SSE passthrough: se `body.stream && upstreamResp.body` → `new Response(upstreamResp.body, { headers: { 'Content-Type': 'text/event-stream', 'Cache-Control': 'no-cache, no-transform', 'Connection': 'keep-alive' } })`
- Non-streaming JSON passthrough: `await upstreamResp.text()` + `new Response(text, { status, headers: { 'Content-Type': 'application/json' } })`
- 502 com detalhe PT-PT se `fetch(OPENAI_URL, ...)` falhar (rede)
- GET retorna 405 `{ error: 'Apenas POST suportado.' }`

[Trace: ADR-10 §3.3 Abordagem B, §7 R5, §8 row S4; espelho `app/api/anthropic/proxy/route.ts:1-177`]

**AC2 — `lib/agent/sse-lines.ts` (extracção `iterateSseData`) + refactor `inference-transport.ts`**

[Trace: ADR-10 §3.3 "Nota DRY de baixo risco", §5 "lib/agent/sse-lines.ts — NOVO"]

**AC3 — `OpenAIInferenceTransport.classify()` (non-streaming via proxy)**
- POST a `/api/openai/proxy` com body `{ model: opts.model ?? DEFAULT_OPENAI_CLASSIFIER_MODEL, messages: [{ role:'system', content: systemPrompt }, { role:'user', content: userPrompt }], response_format: { type:'json_object' }, max_tokens: opts.maxTokens ?? 1024, temperature: opts.temperature ?? 0 }` (sem `stream`)

**AC4 — `OpenAIInferenceTransport.execute()` (streaming SSE OpenAI via proxy)**
- POST a `/api/openai/proxy` com body `{ model: opts.model ?? DEFAULT_OPENAI_EXECUTOR_MODEL, messages: toOpenAIMessages(messages) (local), stream: true, stream_options: { include_usage: true }, ...(tools.length > 0 ? { tools: toolsToOpenAIShape(tools) } : {}) }`
- `!res.ok` → throw `Error` PT-PT; `!res.body` → throw `Error` PT-PT
- Parseia SSE OpenAI via `iterateSseData(res.body)` em loop `for await`:
  - `choices[0].delta.content` → emite `{ type:'text_delta', text }` (LLMStreamEvent validado por `LLMStreamEventSchema.parse`)
  - 1.º chunk de cada `tool_calls[].index`: extrai `index`, `id`, `function.name`, `function.arguments` (geralmente `""`) → guarda em `Map<index, {id, name, argsAccumulator: ""}>` + concatena o fragmento
  - Chunks seguintes do mesmo `index`: concatena `function.arguments` ao `argsAccumulator` (sem `id`/`name`)
  - `finish_reason === 'tool_calls'` OU `data: [DONE]`: para cada entrada do Map → `JSON.parse(argsAccumulator)` (vazio → `{}`) → emite `{ type:'tool_use', id, name, input }` (LLMStreamEvent validado); limpa Map
  - `finish_reason === 'stop'` ou `[DONE]` sem tool calls: termina loop normalmente
  - Chunk de `usage` (com `include_usage:true`): mapeia `prompt_tokens → inputTokens`, `completion_tokens → outputTokens`
  - `[DONE]`: sai do loop
- Após loop: emite `{ type:'done', inputTokens, outputTokens }` (LLMStreamEvent validado)
- `JSON.parse` de accumulator inválido → emite `{ type:'error', message: ... }` + throw `OpenAITransportStreamErrorAlreadyEmitted` (sentinela anti-double-emission local)
- Outer catch: relança erros que já emitiram `error` event; para erros novos, emite `error` event + relança
- `messages.length === 0` → throw; `!opts.runId` → throw

[Trace: ADR-10 §4.1 (fragmentação `tool_calls`), §4.3 (`toOpenAIMessages`), §6.2 (mock fidelity), §8 row S4; espelho `inference-transport.ts:329-503`]
