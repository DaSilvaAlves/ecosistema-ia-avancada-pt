## User Story

Como utilizador do Nexus, quero registar, consultar, editar e apagar as minhas transações financeiras variáveis (uma compra no supermercado, um almoço, um abastecimento) através de um formulário, para que possa manter o registo das minhas despesas e receitas sem depender do chat.

- **AC1:** Existe a rota `app/(app)/financas/page.tsx` (`'use client'`, App Router) — URL `/financas`. A página é alcançável a partir da navegação principal: o `components/ui/Header.tsx` (`:84-111`) **já contém** `<NavLink href="/finance">Finanças</NavLink>` (`:94`) — o item de navegação "Finanças" já existe (label não inventada), mas aponta para `/finance`, rota inexistente. Os restantes `NavLink`s partidos do Header (`/tasks`, `/habits`, `/journal`, `/knowledge`) **não** são tocados — ver Anti-padrões.
  _Trace: FR16, EPIC-3 §5 Story 3.3; [AUTO-DECISION] A1 + A8; R9._

- **AC2:** O botão "+ Nova transação" abre o `TransactionFormModal` em modo `create`. O modal tem os seguintes campos, todos com `label` associado:
  1. **Valor** — input de texto para o montante em euros, formato PT-PT (o utilizador digita `78,70` ou `1.234,56`). Obrigatório.
  2. **Direção** — seletor Saída / Entrada. Default: **Saída**. Determina o sinal de `amount`.
  3. **Categoria** — dropdown com as categorias existentes (nomes). Obrigatório.
  4. **Data** — input de data, default = hoje (ISO `yyyy-MM-dd`). Obrigatório.
  5. **Descrição** — input de texto. Opcional (`TransactionSchema.description` não tem `.min`).
  6. **Conta** — dropdown opcional, default "— Nenhuma —".
  7. **Cartão** — dropdown opcional, default "— Nenhum —".
  _Trace: FR16 (campos da transação), R1/R3/R4/R5._

- **AC3:** Existe o módulo `lib/financas/currencyInput.ts` com duas funções puras exportadas:
  - `parseCurrencyInput(input: string): number` — converte uma string de euros em formato PT-PT para cêntimos inteiros não-negativos. Ex: `'78,70'` → `7870`, `'1.234,56'` → `123456`, `'100'` → `10000`, `'1234,5'` → `123450`. Input inválido ou vazio → lança `Error` com mensagem PT-PT (a UI converte em erro de campo).
  - `centsToInputValue(cents: number): string` — converte cêntimos inteiros para a string editável do input (sem símbolo `€`, sem sinal). Ex: `7870` → `'78,70'`. Usada para pré-preencher o campo Valor em modo `edit`.
  Ambas as funções são puras (sem React/DOM), seguem o estilo de `formatCurrency.ts` (validação fail-fast de input não-finito/não-seguro).
  _Trace: R2, FR16 ("valor EUR formato PT-PT"), AC5 do EPIC-3._

- **AC4:** Ao submeter o `TransactionFormModal` em modo `create`, é criada uma transação via `createTransaction` (de `@/lib/db/repos/transactions`) com:
  - `id` — UUID gerado pela UI (padrão `ProjectFormModal` da Story 2.8)
  - `amount` — cêntimos inteiros: `parseCurrencyInput(valor)` com sinal negativo se direção = Saída, positivo se Entrada
  - `category` — nome selecionado no dropdown
  - `description` — texto digitado (string vazia se não preenchido)
  - `date` — data selecionada (ISO `yyyy-MM-dd`)
  - `accountId` / `cardId` — UUID selecionado ou `null`
  - `recurrenceId` / `installmentId` — **sempre `null`** (transação variável manual)
  - `createdAt` — `Date.now()` (epoch ms — `TransactionSchema.createdAt` é `z.number().int().positive()`)
  _Trace: R1, `TransactionSchema` (`schemas.ts:160-174`)._

- **AC5:** A página `/financas` mostra uma **lista cronológica básica** das transações (mais recente primeiro), consumida via o hook reactivo `useTransactions()`. Cada linha mostra: descrição (ou a categoria, se a descrição for vazia), categoria, data, e o valor formatado via `formatCurrency(amount)` (cêntimos → `€1.234,56`). Saídas e entradas são visualmente distinguíveis (ex: cor — Magenta `#FF006E` para saída, Lime `#39FF14` para entrada). A lista re-renderiza automaticamente ao criar/editar/apagar (reactividade `useLiveQuery`). Estados de loading (`useTransactions` devolve `undefined`) e vazio (array vazio) têm tratamento próprio, à semelhança de `tarefas/page.tsx` (`LoadingSkeleton` / `EmptyState`).
  _Trace: FR16 (Read do CRUD), AC5 do EPIC-3 (formato PT-PT); boundary A6 — lista básica, não vista analítica._

- **AC6:** Cada linha da lista permite **editar** a transação: uma acção de linha abre o `TransactionFormModal` em modo `edit`, pré-preenchido com os valores da transação (o campo Valor pré-preenchido via `centsToInputValue`; a direção inferida do sinal de `amount`). O submit em modo `edit` chama `updateTransaction(id, patch)` (de `@/lib/db/repos/transactions`), preservando `id` e `createdAt` originais.
  _Trace: FR16 (Update do CRUD), `updateTransaction` (`repos/transactions.ts:99-111`)._

- **AC7:** Cada linha da lista permite **apagar** a transação: uma acção de linha chama `deleteTransaction(id)` (de `@/lib/db/repos/transactions`), com confirmação prévia do utilizador, seguindo o padrão de acção destrutiva já existente no codebase (o executor verifica `tarefas`/`projectos` e replica). Erros são capturados e comunicados ao utilizador sem quebrar o render.
  _Trace: FR16 (Delete do CRUD), `deleteTransaction` (`repos/transactions.ts:113-115`)._

- **AC8:** O dropdown de **Categoria** é alimentado por um novo hook reactivo `hooks/useCategories.ts` que envolve `listCategories()` via `useLiveQuery` (espelha `hooks/useTransactions.ts`/`hooks/useAccounts.ts`). ### Modelo de dados — sinal de `amount`

`Transaction.amount` é um inteiro em **cêntimos** (`types/db.ts:117`). Não há campo `type`/`direction` — o **sinal** codifica a direção: negativo = saída (despesa), positivo = entrada (receita). O formulário recolhe a magnitude (sempre não-negativa) e a direção em separado; no submit:

```text
amount = (direção === 'saida' ? -1 : 1) * parseCurrencyInput(valorDigitado)
```

Em modo `edit`, a direção é inferida: `amount < 0` → Saída, `amount >= 0` → Entrada; o campo Valor é `centsToInputValue(Math.abs(amount))`.

### Helper `currencyInput.ts` — contrato

```typescript
// lib/financas/currencyInput.ts
// parseCurrencyInput: string PT-PT de euros → cêntimos inteiros não-negativos
parseCurrencyInput('78,70')     // 7870
parseCurrencyInput('1.234,56')  // 123456
parseCurrencyInput('100')       // 10000   (sem decimais → ,00)
parseCurrencyInput('1234,5')    // 123450  (1 casa → completa para ,50)
parseCurrencyInput('')          // throw Error('Valor inválido — ...')
parseCurrencyInput('abc')       // throw Error
parseCurrencyInput('-5')        // throw Error (a magnitude é sempre não-negativa)

// centsToInputValue: cêntimos → string editável (sem € e sem sinal)
centsToInputValue(7870)         // '78,70'
centsToInputValue(0)            // '0,00'
```

`formatCurrency` (Story 3.1) faz o sentido **inverso** com símbolo `€` — é para **display** na lista, não para o input. O `currencyInput.ts` é o helper de **entrada/edição**. Ambos vivem em `lib/financas/` (camada de dados, funções puras).

**Atenção ao arredondamento:** o parsing deve produzir cêntimos exactos sem erro de vírgula flutuante (ex: `parseFloat('0.1') * 100` não dá `10` exacto). Fazer o parsing por manipulação de string (separar parte inteira e decimal, normalizar a 2 dígitos decimais), não por aritmética de `float`. Precedente do estilo: `formatCurrency.ts` evita `Intl`/`toLocaleString` por determinismo.

### Modo `edit` — preservar `id` e `createdAt`

`updateTransaction(id, patch)` aceita um `Partial<Transaction>` e valida com `TransactionSchema.partial()` (`repos/transactions.ts:99-111`). O modal em modo `edit` recebe o `Transaction` original em `initialValue`; no submit, `id` e `createdAt` **não são alterados** — só os campos editáveis entram no `patch`. Padrão idêntico ao `ProjectFormModal`.

### Hooks novos — espelhar `useAccounts.ts`

`hooks/useAccounts.ts` é o molde exacto (já lido): `'use client'`, `useLiveQuery(() => listAccounts(), [])`, retorna `Account[] | undefined`. `useCategories` e `useCards` replicam-no trocando o repo. `useCategories` retorna `Category[] | undefined`; `useCards` retorna `Card[] | undefined`.
