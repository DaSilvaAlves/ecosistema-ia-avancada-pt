### Contrato da Web Speech API (protocolo real — para fidelidade do mock)

```typescript
// Shape real de SpeechRecognitionEvent (onresult)
interface SpeechRecognitionEvent {
  results: SpeechRecognitionResultList; // indexável: results[0] = SpeechRecognitionResult
  // results[0][0] = SpeechRecognitionAlternative { transcript: string; confidence: number }
  // results[0].isFinal: boolean
}

// Shape real de SpeechRecognitionErrorEvent (onerror)
interface SpeechRecognitionErrorEvent {
  error: SpeechRecognitionErrorCode; // 'not-allowed' | 'no-speech' | 'network' | 'audio-capture' | ...
  message: string;
}

// Configuração obrigatória da instância
recognition.lang = 'pt-PT';     // SEMPRE — nunca vazio nem 'en-US'
recognition.continuous = false;  // Uma frase → uma transcrição
recognition.interimResults = false; // Só resultado final
```

O mock de teste DEVE reflectir este shape exacto (`mock-protocol-fidelity.md`). Um mock que usa `event.result.transcript` (sem o `s` e sem `[0][0]`) passa nos testes mas falharia em produção.

### Cleanup de `SpeechRecognition` no unmount

É obrigatório parar o reconhecimento quando o componente desmonta — caso contrário, o browser pode manter o microfone activo e o callback `onresult`/`onerror` pode disparar em componente já desmontado. Padrão:

```typescript
useEffect(() => {
  return () => {
    if (recognitionRef.current) {
      recognitionRef.current.onresult = null;
      recognitionRef.current.onerror = null;
      recognitionRef.current.onend = null;
      recognitionRef.current.stop();
    }
  };
}, []);
```

### Decisões de design tomadas

**DEV-DECISION D-7.2-COMPOSE** — Composição no `InputBox`. O `useVoice({ voiceState, onTranscript })` recebe o objecto completo do `useVoiceModeState` da 7.1 (não cria estado paralelo — AC5). O hook lê `voiceState.state` (via `stateRef` espelhado por `useEffect` para evitar stale closure nos handlers) e chama `toggle`/`setProcessing`/`setError`. A instância de `SpeechRecognition` é efémera: criada em `start()`, descartada em `onresult`/`onerror`/`onend`/`stop`/unmount (`teardownRecognition` idempotente). O estado de UI vive exclusivamente no `useVoiceModeState`.

**DEV-DECISION D-7.2-TRANSCRIPT-CONTRACT** — Opção (b) da story: a transcrição é injectada no campo de texto do `InputBox` (precedente 6.13 — "injectar no pipeline existente, não criar fluxo novo"). O `onTranscript` faz `setText` (anexa ao texto existente com espaço se já houver conteúdo) e depois `voice.reset()` para voltar a `idle` (o `processing` é transitório). A 7.3 consome o texto pelo pipeline `onSend` existente sem alterar ficheiros da 7.2.

**Ressalva PO #1 honrada (`onend` sempre dispara)** — `gotResultRef` (um `useRef`, NÃO `state`, para evitar stale closure) é marcado `true` em `onresult` E em `onerror`. O handler `onend` só chama `setError(no-speech)` se `gotResultRef.current === false`. Isto impede que o caminho feliz (`onresult` → `onend`) caia erradamente em erro. Coberto pelos testes "onend após onresult NÃO dispara setError" e "onerror → onend não re-dispara".

**Ressalva PO #2 honrada** — Instanciação via `window.SpeechRecognition ?? window.webkitSpeechRecognition` (`createRecognition()`), não apenas detecção.

**Ressalva PO #3 honrada** — Todos os caminhos de falha viram `setError` explícito (AC4): `not-allowed`/`service-not-allowed` → "Permissão de microfone negada"; `no-speech` → "Sem resposta de voz detectada"; outros códigos → "Erro de reconhecimento: {código}"; `onend` sem resultado → "Sem resposta de voz detectada"; transcript vazio → "Sem resposta de voz detectada". Nunca sucesso silencioso.

**Tipos do protocolo Web Speech (ADITIVO)** — O `lib.dom.d.ts` do TypeScript inclui `SpeechRecognitionResult`/`Alternative`/`ResultList` mas NÃO `SpeechRecognition`, `SpeechRecognitionEvent`, `SpeechRecognitionErrorEvent`, nem os globais `window.SpeechRecognition`/`webkitSpeechRecognition`.
