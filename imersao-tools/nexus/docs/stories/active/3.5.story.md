**A Story 3.5 NÃO recria nenhum destes artefactos.** O seu scope é entregar a **camada de UI** de FR18:

1. **`AccountFormModal`** — modal criar/editar uma conta bancária (nome, tipo, saldo).
2. **`CardFormModal`** — modal criar/editar um cartão de crédito (nome, conta, dia de fecho, dia de vencimento, limite).
3. **`AccountsList`** e **`CardsList`** — listas das contas e cartões na page `/financas`.

5. **`lib/financas/balanceInput.ts`** — helper de entrada para saldo de conta (suporta sinal negativo) e limite de cartão (opcional). Análogo a `currencyInput.ts`, extraído para testabilidade.
6. **Guards de eliminação** — `deleteAccount` bloqueado se a conta tiver cartões; `deleteCard` com confirmação.

**O que a Story 3.5 NÃO entrega:**
- A **vista de cartões** (fatura corrente + próxima fatura + prestações) — isso é a **Story 3.8** (`EPIC-3.md` §5).

- As **compras parceladas** vinculadas a cartão — isso é a **Story 3.6** (a 3.6 depende desta 3.5 — sem CRUD de cartões não há cartão a que vincular uma prestação).
- Qualquer **cálculo de fecho de fatura** — a 3.5 apenas regista `closingDay`/`dueDay`; o cálculo é da Story 3.8.
- Movimento automático de saldo por transação — `updateBalance` (repo, Story 3.1) existe mas a sua activação por transação é de stories de vista futuras, não da 3.5.

## User Story

Como utilizador do Nexus, quero registar, consultar, editar e apagar as minhas contas bancárias (com o respectivo saldo) e os meus cartões de crédito (com o dia de fecho de fatura e o dia de vencimento), através de formulários na página de Finanças, para que possa depois associar transações e compras parceladas às contas e cartões correctos e ter uma visão fiel do meu património.

## User Story (formal)

**As a** utilizador do Nexus,
**I want** criar, consultar, editar e apagar as minhas contas bancárias (com saldo, podendo estar a descoberto) e os meus cartões de crédito (com dia de fecho de fatura, dia de vencimento e limite opcional), a partir de separadores na página de Finanças,

- **AC1:** Existe `lib/financas/balanceInput.ts` — módulo de funções **puras** (sem Dexie, sem React) que exporta:
  - `parseBalanceInput(input: string, negative: boolean): number` — converte a string de euros PT-PT (magnitude) para cêntimos inteiros, aplicando o sinal. Reutiliza `parseCurrencyInput` para a magnitude. `negative === true` → resultado negativo; `false` → positivo. Magnitude zero → `0` (sem `-0`).
  - `balanceToInput(cents: number): { magnitude: string; negative: boolean }` — inverso, para pré-preencher o modo `edit`: `magnitude` via `centsToInputValue(Math.abs(cents))`, `negative = cents < 0`.
  - `parseCardLimit(input: string): number | null` — string vazia (ou só espaços) → `null`; caso contrário → cêntimos inteiros não-negativos via `parseCurrencyInput`.

### Repo isolation — regra herdada

A page `/financas` declara explicitamente (`page.tsx:53`): "Repo isolation: zero `db.*` directos — apenas funções dos repos." A Story 3.5 mantém esta regra: o guard de eliminação de conta (AC9) usa `listCardsByAccount(id)` (ou filtra o array `cards` já carregado pelo hook `useCards`), nunca `db.cards.*` directo.

### `createAccount`/`createCard` recebem o objecto completo

Ao contrário de `createFinanceRecurrence` (Story 3.4, que usa `Omit<...,'id'|'createdAt'>`), os repos `createAccount(input: Account)` e `createCard(input: Card)` recebem o objecto **completo**. O modal/parent gera `id` (`crypto.randomUUID()`) e, para `Account`, `createdAt` (`Date.now()`) — padrão idêntico ao `TransactionFormModal` da Story 3.3. `Card` não tem `createdAt`.

### Saldo negativo — `balanceInput.ts`

`parseCurrencyInput` (Story 3.3) só devolve magnitudes não-negativas e `centsToInputValue` exige cêntimos não-negativos. Como `Account.balance` aceita sinal livre, `balanceInput.ts` é a camada que combina magnitude + sinal:

```typescript
export function parseBalanceInput(input: string, negative: boolean): number {
  const magnitude = parseCurrencyInput(input); // cêntimos >= 0
  if (magnitude === 0) return 0;               // evita -0
  return negative ? -magnitude : magnitude;
}

export function balanceToInput(cents: number): { magnitude: string; negative: boolean } {
  return { magnitude: centsToInputValue(Math.abs(cents)), negative: cents < 0 };
}

export function parseCardLimit(input: string): number | null {
  return input.trim() === '' ? null : parseCurrencyInput(input);
}
```

O seletor de sinal do `AccountFormModal` é o mesmo padrão visual do seletor "Direção" do `TransactionFormModal` (Story 3.3), com os rótulos "A favor" / "A descoberto".

### Guard de eliminação de conta (AC9)

`Card.accountId` é non-nullable (`CardSchema.accountId: z.string().uuid()`). Apagar uma conta com cartões deixaria os cartões com uma FK inválida. O handler verifica `cards.some(c => c.accountId === id)` (o array `cards` já vem do hook `useCards()` reactivo na page) — se houver cartões, aborta com mensagem no toast e não chama `deleteAccount`.
