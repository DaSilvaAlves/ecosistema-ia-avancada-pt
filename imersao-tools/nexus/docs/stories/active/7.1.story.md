## Contexto

A Story 7.1 entrega a **fundação visual do modo voz no browser**: o `VoiceModeButton` — botão/toggle microfone no chat principal com 5 estados de render (idle / a-ouvir / a-processar / erro / não-suportado). **Não implementa qualquer lógica de Web Speech API** — essa é a Story 7.2. O componente expõe uma interface prop-driven que a 7.2 preencherá com a lógica real de reconhecimento.

### Posição no Epic 7

| Story | Responsabilidade |
|-------|-----------------|
| **7.1 (esta)** | UI: botão + estados visuais + hook de estado local |
| 7.2 | Lógica: `SpeechRecognition` PT-PT, transcrição → texto |
| 7.3 | Roteamento: texto transcrito → cérebro multi-intent |
| 7.4 | Síntese: `SpeechSynthesis` PT-PT lê resposta do cérebro |

### Contexto arquitectural

- `InputBox.tsx` já contém um `<Mic>` (ícone Lucide) como **placeholder visual idle-only** — referenciado no JSDoc: "GAP-2 (PO Pax 08/05/2026) — `<Mic>` é placeholder visual idle-only; funcionalidade voice completa fica para Epic 7 (FR77-80)". A 7.1 **substitui/integra** este placeholder pelo componente real.
- A arquitectura (`architecture-v2.md` §3, §6) define `useVoice.ts` como hook client-side — o `VoiceModeButton` integra com esse hook (criado na 7.2); esta story cria a forma do contrato de interface.
- Web Speech é **browser nativo** — corre 100% client-side, sem server. A 7.1 não cria qualquer route server-side.
- CLI First (Constitution Artigo I): o `VoiceModeButton` é camada UI (terciária). O Nexus opera 100% via chat texto/CLI — a UI de voz é conveniência, nunca pré-requisito de qualquer funcionalidade core. Não há dependência do `VoiceModeButton` em nenhum fluxo de dados do cérebro.

### Design system

O componente segue o **Design System [IA]AVANÇADA PT** (`.claude/rules/design-system-ia-avancada.md`):
- Fundo escuro `#04040A`; superfícies com glassmorphism (`rgba(255,255,255,0.025)` + `border: 1px solid rgba(255,255,255,0.08)`)
- Paleta: Cyan `#00F5FF` (estado idle/activo), Lime `#39FF14` (a-ouvir, estado positivo), Magenta `#FF006E` (erro), Grey `#8892A4` (não-suportado), White `#F0F4FF` (texto)
- `border-radius` mínimo 6px; transições `0.25s cubic-bezier(0.4, 0, 0.2, 1)`

## User Story

**Como** utilizador do Nexus v2,
**quero** ver um botão de microfone no chat principal com estados visuais claros (inactivo, a ouvir, a processar, erro, browser não suportado),
**para que** saiba visualmente quando o modo voz está disponível, activo e em que estado se encontra — sem precisar de saber nada sobre a tecnologia subjacente.

## Acceptance Criteria

> Traçados directamente a `PRD-NEXUS-V2.md` §6.14 FR77 + `EPIC-7.md` §5 row 7.1 + `EPIC-7.md` §8 (lição A3 `react-component-test-criteria.md`). Wording preservado dos documentos canónicos; nenhum AC inventado.

**AC1** — O componente `VoiceModeButton` existe em `components/chat/VoiceModeButton.tsx` e é exportado. Renderiza um botão de microfone acessível (`aria-label` PT-PT descritivo, `role="button"`, `aria-pressed` dinâmico conforme estado).

**AC2** — O componente tem exatamente 5 estados visuais distintos, mapeados para as cores do design system:

| Estado (`VoiceModeState`) | Cor / aparência | Quando |
|--------------------------|-----------------|--------|
| `idle` | Cyan `#00F5FF`, sem pulsação | Padrão — modo voz disponível mas inactivo |
| `listening` | Lime `#39FF14`, animação de pulsação | A reconhecer voz |
| `processing` | Cyan `#00F5FF`, spinner/indicador | Transcrição/envio em curso |
| `error` | Magenta `#FF006E`, ícone de erro | Erro de microfone / permissão negada |
| `unsupported` | Grey `#8892A4`, desactivado | Browser não suporta Web Speech API |

**AC3** — O estado `unsupported` é activado quando `'SpeechRecognition' in window === false && 'webkitSpeechRecognition' in window === false` (verificação client-side no mount). Neste estado, o botão tem `disabled` e `aria-label` que indica "Modo voz não suportado neste browser".

**AC4** — O componente aceita a prop `onVoiceToggle?: (active: boolean) => void` — callback invocado quando o utilizador clica para activar/desactivar o modo voz. A 7.1 invoca o callback mas **não implementa lógica de speech** — a 7.2 fornecerá a implementação real. No estado `unsupported` ou `processing`, o clique não invoca o callback.

**AC5** — O hook `useVoiceModeState` em `hooks/useVoiceModeState.ts` gere o estado local do `VoiceModeButton`. Expõe a interface completa `{ state: VoiceModeState; toggle: () => void; setError: (msg: string) => void; setProcessing: () => void; reset: () => void; errorMessage: string; isSupported: boolean }`. O hook detecta suporte no browser (mount) e inicializa em `unsupported` se necessário. [CR Iter 1 C1: interface alinhada à implementação real — `setProcessing`/`reset`/`errorMessage`/`isSupported` fazem parte do contrato que a Story 7.2 herda; `setProcessing` incluído por should-fix #2 do PO.]

**AC6** — O `VoiceModeButton` é integrado no `InputBox.tsx` substituindo o ícone `<Mic>` placeholder existente. Em modo `idle`, ocupa o mesmo espaço visual do placeholder anterior. A integração não altera o comportamento existente do `InputBox` (testes da Story 0.4/1.9 continuam a passar).

**AC7** — Existem testes de componente em `tests/unit/components/chat/VoiceModeButton.test.tsx` com 5 cenários de estado — um por estado de render (idle, listening, processing, error, unsupported) — mais verificações de acessibilidade (anúncio `aria-live`) e do caso não-interactivo sem handler. Cada cenário de estado verifica: (a) a cor/classe correcta está presente, (b) o `aria-label` PT-PT está correcto, (c) o comportamento de clique é o esperado. [Trace: `react-component-test-criteria.md` — 5 estados ≥ 3 → teste de componente obrigatório; `EPIC-7.md` §8 lição A3. CR Iter 1 C2: spec alinhada à suite real — 5 cenários de estado + verificações de a11y/não-interactivo.]

**AC8** — O componente é acessível: `aria-live="polite"` para anunciar mudanças de estado aos leitores de ecrã; `aria-pressed` sincronizado com o estado activo/inactivo; foco via teclado (Tab/Enter/Space).

**AC9** — O componente funciona visualmente em Chrome/Edge (browsers com Web Speech suportada). Em Firefox, entra em `unsupported` com mensagem PT-PT. Não há crash em nenhum browser.

export type VoiceModeState = 'idle' | 'listening' | 'processing' | 'error' | 'unsupported';

export function useVoiceModeState() {
  // detectar suporte no mount (client-side only)

### Contrato de interface para a 7.2

A Story 7.2 irá receber o `VoiceModeButton` + `useVoiceModeState` e:
- Ligar `toggle` ao `SpeechRecognition.start()` / `stop()`
- Chamar `setProcessing()` quando o reconhecimento terminar e o texto for enviado
- Chamar `setError(msg)` em caso de `onerror` do `SpeechRecognition`
- O contrato de props do `VoiceModeButton` **não muda** na 7.2 — a 7.1 define a interface estável

### Detectar suporte sem instanciar

```typescript
// Verificação correta — não instancia SpeechRecognition
const isSupported =
  typeof window !== 'undefined' &&
  ('SpeechRecognition' in window || 'webkitSpeechRecognition' in window);
```

Esta verificação é segura em SSR (Next.js) porque verifica `typeof window !== 'undefined'` antes de aceder ao objeto `window`.
