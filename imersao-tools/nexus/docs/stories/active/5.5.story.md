### `searchJournalEntries` JÁ EXISTE mas tem limitações a corrigir

**`searchJournalEntries` em `v2/lib/db/repos/journal-entries.ts:67-85`:**

```ts
export async function searchJournalEntries(query: string): Promise<JournalEntry[]> {
  const needle = query.trim().toLowerCase();
  if (needle === '') return [];
  const all = await db.journal_entries.toArray();
  return all
    .filter((entry) => {
      const haystack = [...].join(' ').toLowerCase();
      return haystack.includes(needle);    // ← single-needle, sem tokenização AND
    })
    .sort((a, b) => b.date.localeCompare(a.date));
}
```

| Lógica inline no repo | Não testável sem Dexie | Extrair para helper puro `lib/diario/pesquisa.ts` |

## User Story

Como utilizador do Nexus (o Eurico), quando estou na página do diário, quero poder pesquisar nas minhas entradas por palavras ou expressões — e ver os resultados com um excerto do texto onde a correspondência aparece, com o termo destacado — para que consiga encontrar rapidamente o que escrevi sobre um tema específico sem percorrer todas as entradas manualmente.

## Dev Notes

- **`searchJournalEntries` existe mas a lógica de matching fica no helper puro.** Refactorização (T3) é obrigatória — o EPIC-5 §5 diz "lógica em `lib/diario/**`", não no repo. A interface pública mantém-se. [Source: lib/db/repos/journal-entries.ts:67-85; EPIC-5 §5]

- **Sem indexação dedicada (decisão explícita e confirmada).** O docstring da `searchJournalEntries` é explícito: "sem índice full-text dedicado (não há FR42-46 que exija indexação; o volume é baixo, 1/dia)". O gate `@qa` não deve levantar Major por ausência de índice. Se o CodeRabbit levantar, defender com este docstring. [Source: journal-entries.ts:63-65]

- **Normalização NFD para PT-PT.** `String.prototype.normalize('NFD').replace(/\p{M}/gu, '')` sem dependência externa. `\p{M}` (Unicode combining marks) requer a flag `u` — suportado em todos os runtimes alvo do Nexus (Edge + browser). [Source: AC1; `language-standards.md`]

- **AND multi-termo — não OR.** A função actual usa `includes(needle)` — a query completa como string única. A 5.5 tokeniza e exige que todos os tokens estejam presentes. Sem OR, sem NEAR — não existe FR que o exija. [Source: AC1; FR45 "standard"]

- **`highlightMatches` e `extractExcerpt` são síncronos.** Operam sobre strings em memória. `searchJournalEntries` é async (Dexie), mas o highlight/excerpto são aplicados depois, sobre a lista já retornada. [Source: journal-entries.ts:67-85]

- **Padrão prop-driven herdado da 5.3/5.4.** `DiarioSearchResults` recebe `onSelect` como prop (não importa `JournalEntryModal` directamente). Coerente com `[DEV-D-5.4-CALLBACK]` — o parent (`page.tsx`) gere a abertura do modal. [Source: DEV-D-5.4-CALLBACK; components/diario/JournalEntriesList.tsx]

- **Debounce no input (≤300ms).** `useEffect` + `setTimeout` — sem biblioteca. `searchJournalEntries` é in-memory mas debounce evita re-renders a cada keystroke. [Source: AC3]

- **Modo pesquisa vs modo normal.** Quando `searchQuery` preenchida: ocultar `MoodHeatmap` + `JournalEntriesList`, mostrar `DiarioSearchResults`. Quando vazia: voltar ao modo normal. Sem remover o heatmap do DOM — condicional simples. [Source: AC3; app/(app)/diario/page.tsx]

- **`extractExcerpt` — ordem de campos.** Verificar `bodyMarkdown` → `structuredAI.whatHappened` → `whatLearned` → `whatFelt`. Se nenhum campo tiver match (não deve acontecer pós-filtragem), devolver início do `bodyMarkdown`. [Source: JournalEntry types/db.ts:228]
