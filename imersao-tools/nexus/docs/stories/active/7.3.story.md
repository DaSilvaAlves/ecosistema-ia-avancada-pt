## Decisão de Design Central — D-7.3-PIPELINE-ROUTE

> Resolução da tensão entre FR79 "directo" e D-7.2-TRANSCRIPT-CONTRACT (opção b). Obrigatória pelo handoff de arranque 7.3 §3 e pela Constitution Artigo IV (No Invention).

### Fontes citadas textualmente

**PRD §6.14 FR79** (fonte primária, citação literal):

**EPIC-7.md §2 ("Base Epic 1")** (citação literal):

O modo voz **não cria fluxo novo** de processamento — transcreve para texto e injecta no pipeline existente do Epic 1, exactamente como a 6.13 fez para o texto do Telegram."

**EPIC-7.md §5 row 7.3** (citação literal):

**D-7.2-TRANSCRIPT-CONTRACT opção b** (decisão fechada na Story 7.2, Change Log 24/06/2026):
> "a transcrição é injectada no campo de texto do InputBox (precedente 6.13 — 'injectar no pipeline existente, não criar fluxo novo'). O `onTranscript` faz `setText` (anexa ao texto existente com espaço se já houver conteúdo) e depois `voice.reset()` para voltar a `idle` (o `processing` é transitório). A 7.3 consome o texto pelo pipeline `onSend` existente sem alterar ficheiros da 7.2."

### Análise das opções

| Opção | Descrição | Avaliação |
|-------|-----------|-----------|
| **A — Manual-com-revisão** | Transcrição injectada no campo via `setText`; utilizador revê e carrega Enviar → `handleSend` → `stream.submit` → cérebro. Já implementada pela D-7.2 opção b. A 7.3 é verificação E2E + ajustes finos. | Compatível com todos os traços. "Directo" refere-se a ausência de transformação do texto, não a disparo automático. Zero fluxo novo. |
| **B — Envio automático** | `onTranscript` chama `onSend(transcript)` ou `submit()` directamente, sem o utilizador carregar Enviar. Implicaria adicionar lógica de disparo no `useVoice` ou no `InputBox.onTranscript`, criando um segundo caminho de disparo para `handleSend`. | Contradiz "não criar fluxo novo" (EPIC-7 §2 + §5 row 7.3 + precedente 6.13). Distribui o gatilho de envio entre o hook de voz e o pipeline de envio (≥2 camadas), o que exigiria análise de ciclo de vida (`internal-state-contract-gate.md`) e gate `@architect`. |

### DESIGN-DECISION D-7.3-PIPELINE-ROUTE

**Escolha: Opção A — Manual-com-revisão.**

**Justificação com trace:**
1. A D-7.2-TRANSCRIPT-CONTRACT (opção b, fechada) já implementa o caminho: `onTranscript` → `setText` → texto no campo → utilizador envia → `onSend` → `stream.submit(text)` → cérebro. O texto transcrito **já chega ao cérebro** pelo pipeline normal de envio, sem modificações.
2. "Directo" em FR79 significa que o texto transcrito vai para o cérebro **sem transformação** (não passa por um parser intermédio, não é reformatado) — coerente com a literalidade de JARVIS.txt L60-67 (a transcrição é o input directo ao cérebro). Não implica disparo automático sem revisão.
3. A opção B contradiria a restrição inegociável de ambos os documentos canónicos: EPIC-7 §2 ("não cria fluxo novo") e §5 row 7.3 ("não cria fluxo novo, precedente 6.13").
4. Código real verificado (InputBox.tsx): o `onTranscript` injecta via `setText`, o `voice.reset()` repõe `idle`, e `submit()` (linha 137-141) chama `onSend?.(trimmed)` → `ChatPanel.handleSend` → `stream.submit(text)`. O caminho está fechado. A 7.3 verifica-o end-to-end.

**Alternativa rejeitada:** Opção B (envio automático). Razão: criaria um segundo caminho de disparo para `handleSend` a partir do hook de voz — constitui "criar fluxo novo" no sentido da restrição de ambos os documentos. Adicionalmente, distribuiria o gatilho de envio por ≥2 camadas (hook `useVoice` + `InputBox.submit`), exigindo análise de ciclo de vida e gate `@architect` sem benefício justificado.

**Gate de entrada `@architect` necessário:** Não — a 7.3 não distribui estado por ≥2 camadas e não cria fluxo novo. O pipeline `onSend` → `stream.submit` existe e está verificado. Aplicar `@architect` seria gate desnecessário.

## User Story

**Como** utilizador do Nexus v2,
**quero** que quando digo uma frase por voz ela chegue ao cérebro multi-intent e seja processada exactamente como se eu a tivesse escrito,
**para que** possa criar tarefas, registar despesas ou definir lembretes apenas com a voz, sem tocar no teclado — especialmente útil a conduzir ou com as mãos ocupadas.

## Acceptance Criteria

> Traçados directamente a `PRD-NEXUS-V2.md` §6.14 FR79 + `EPIC-7.md` §5 row 7.3 + `EPIC-7.md` §6 AC1 + D-7.3-PIPELINE-ROUTE. Wording preservado dos documentos canónicos; nenhum AC inventado.
