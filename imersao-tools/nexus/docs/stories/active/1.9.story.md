## User Story

**As a** Eurico (utilizador único do Nexus v2) a interagir com o chat principal,
**I want** poder escrever um prompt em PT-PT no input always-visible, ver os ToolCards a aparecerem em tempo real à medida que o servidor executa as tools via SSE stream, confirmar ou cancelar acções com confidence < 70% directamente nos cards, e ter a opção de anular toda a execução no toast de undo durante 30 segundos,
**so that** o killer flow descrito no PRD FR1/FR2/FR3/FR5/FR6 e no Flow 2 da front-end-spec fique operacional de ponta a ponta — o prompt multi-intent cria entidades em tempo real, persistidas em Dexie client-side (RESOLVED-2 da Story 1.5), com confirmação visual e reversibilidade, completando o AC1, AC2, AC3 e AC4 do Epic 1.

## Acceptance Criteria

- **AC1:** Novo hook `hooks/useAgentStream.ts` exporta `useAgentStream()`:
  ```typescript
  export interface UseAgentStreamResult {
    submit: (prompt: string) => void;
    isStreaming: boolean;
    currentRunId: string | null;
    events: ExecutorSSEEvent[];
    error: string | null;
    reset: () => void;
  }
  export function useAgentStream(): UseAgentStreamResult
  ```
  - `submit(prompt)` faz `fetch('/api/agent/prompt', { method: 'POST', body: JSON.stringify({ prompt }) })` e itera o `ReadableStream` via `response.body.getReader()`
  - Cada linha `data: <JSON>\n\n` é parseada e adicionada ao array `events` via `setState` imutável
  - O hook deteta `data: [DONE]\n\n` e define `isStreaming = false`
  - Erros de rede/fetch são capturados e expostos em `error` (mensagem PT-PT)
  - O hook é `'use client'` — nunca importado em Server Components

- **AC2:** Persistência Dexie client-side (RESOLVED-2 da Story 1.5) implementada dentro do `useAgentStream` hook:
  - Ao receber evento `meta (phase: 'start')`: invocar `db.agentRuns.startRun({ runId, prompt, modelClassifier, modelExecutor, startedAt })`; o `runId` vem do evento
  - Ao receber evento `tool_complete`: invocar `db.agentRuns.appendToolCall(runId, { toolName, args, result, durationMs, reverted: false })`
  - Ao receber evento `done`: invocar `db.agentRuns.finishRun(runId, { status, intents, inputTokens, outputTokens, durationMs, errorMessage })`
  - Ao receber evento `done` com status `'success'` ou `'partial'`: persistir `ChatMessage` em Dexie com `{ role: 'agent', agentRunId: runId, content: texto acumulado dos `text_delta`, timestamp: Date.now() }`
  - Dexie NÃO é importado em nenhum módulo com `runtime = 'edge'`

- **AC3:** Novo componente `components/chat/ToolCard.tsx` implementa os 6 estados definidos na front-end spec §4.1:
  - Props: `ToolCardProps` conforme spec §4.1 (toolName, state, args, result?, error?, confidence?, onConfirm?, onCancel?, onEdit?, onRetry?)
  - Estado `loading`: border Cyan pulsing, background Cyan 4%, ícone `<Loader2>` spin, texto "A processar..."
  - Estado `success`: border Lime, background Lime 4%, ícone `<Check>`, título da acção em White
  - Estado `error`: border Magenta, background Magenta 4%, ícone `<X>`, string de erro em Grey, botão "Tentar de novo" se `onRetry` fornecido
  - Estado `preview-required`: border Gold pulsing slow, background Gold 4%, ícone `<AlertTriangle>`, botões "Confirmar e gravar" / "Cancelar" — ao clicar Confirmar: chama `onConfirm()` e muda para `loading`; ao clicar Cancelar: chama `onCancel()` e muda para `reverted`
  - Estado `reverted`: border Grey dashed, background 2%, ícone `<Undo2>`, título em Grey com strikethrough
  - Estado `interrupted`: border Gold âmbar, background 2%, ícone `<AlertCircle>`, texto "Interrompida — tentar de novo?"
  - Transição entre estados: 250ms ease-out; aparição: fade-in 200ms + translateY(8px → 0)
  - Tokens exactos conforme spec §4.1: border-radius 12px, padding 12px 16px, tipografia Inter 600 0.9rem (título), Inter 400 0.85rem (conteúdo), JetBrains Mono 0.8rem (datas, valores)

- **AC4:** Quando a UI recebe evento SSE `preview_request`, o ToolCard correspondente entra em estado `preview-required`. O utilizador confirma ou cancela:
  - **Confirmar**: a UI envia `POST /api/agent/confirm { runId, toolName, action: 'confirm' }` → o KvConfirmationProvider no server resolve → executor executa a tool → SSE emite `preview_confirmed` + `tool_complete` → ToolCard muda para `loading` depois `success`
  - **Cancelar**: a UI envia `POST /api/agent/confirm { runId, toolName, action: 'cancel' }` → executor emite `tool_error` → ToolCard muda para `reverted`
  - O chat input permanece **bloqueado** (opacity 60%, desactivado) durante preview pending — não é possível enviar outro prompt enquanto aguarda confirmação
  - Timeout de 60s (conforme `CONFIRM_TTL_SECONDS`): se o servidor não receber resposta no KV, o executor cancela automaticamente; o ToolCard transita para `reverted` ao receber o `tool_error` correspondente

- **AC5:** Novo componente `components/chat/UndoToast.tsx` implementa a spec §4.3:
  - Aparece bottom-center, 24px do bottom, z-index 100, após evento SSE `done` se `runId` é válido e `undo_registered` foi recebido para pelo menos um tool call
  - Texto: `"N acções criadas. Anular tudo?"` onde N é o count de `tool_complete` recebidos na run
  - Progress bar 3px Cyan, 100% → 0% em 30s linear (`UNDO_TTL_SECONDS` de `lib/agent/undo.ts`)
  - Hover sobre toast: pausa countdown (CSS `animation-play-state: paused`)
  - Ao chegar a 0s: fade-out 200ms, sem acção
  - Botão "Anular": fundo transparente, border 1px Cyan; ao clicar:
    1. Envia `POST /api/agent/undo { runId }` (endpoint já existente em Story 1.7)
    2. Se 200 `{ reverted: N }`: invocar `db.agentRuns.markRunReverted(runId)` (Dexie client-side), mudar todos os ToolCards da run para estado `reverted`, mostrar toast Lime "Anulado · N acções revertidas" (4s, sem countdown)

  - Empilhamento: máximo 3 toasts simultâneos; 4.º descarta o mais antigo (FIFO)

### Padrão SSE consumer (referência para @dev)

```typescript
// hooks/useAgentStream.ts — padrão recomendado para consumir SSE no browser
// 'use client' obrigatório — nunca importar em Server Component

async function consumeStream(prompt: string) {
  const response = await fetch('/api/agent/prompt', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ prompt }),
  });

  if (!response.ok || !response.body) {
    throw new Error(`Erro do servidor: ${response.status}`);
  }

  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split('\n\n');
    buffer = lines.pop() ?? '';
    for (const line of lines) {
      if (line.startsWith('data: ')) {
        const raw = line.slice(6).trim();
        if (raw === '[DONE]') return; // stream terminou
        const event = JSON.parse(raw) as ExecutorSSEEvent;
        // dispatch event para state...
      }
    }
  }
}
```
