### Decisões autónomas do SM (para ratificação `@po`)

[AUTO-DECISION A1] **1 ficheiro de tools** para as 6 tools de finanças: `lib/agent/tools/finance.ts`. Razão: todas as 6 tools pertencem ao domínio `'finance'` e partilham o mesmo contexto de repos; não há subdivisão natural como tasks/projects. Alternativa "2 ficheiros (write/read)" descartada — artificioso, sem ganho de legibilidade.

[AUTO-DECISION A2] **Domínio `'finance'`** para as 6 tools. Confirmado em `lib/agent/classifier.ts:38` — `ALL_DOMAINS` inclui `'finance'`. O classifier já sabe classificar intents de finanças. Nenhuma alteração ao classifier necessária — as tools ficam disponíveis via `toolRegistry.byDomain('finance')` automaticamente após o `import './finance'` no barrel.

[~~AUTO-DECISION A3~~ — RESOLVIDO PELA PO (PO-VALIDATION §3, decisão de produto não-delegável)] **`montante: z.number().int().positive('montante deve ser positivo em cêntimos')` — cêntimos inteiros, SEM fallback a string.** A tool é sempre chamada pelo LLM Sonnet via executor (nunca com input cru do utilizador): o Sonnet emite `7870` directamente, não `"€78,70"`. Não há parsing PT-PT dentro das tools. `parseCurrencyInput` continua a servir a UI da Story 3.3 mas **não é usado pelas tools 3.11**. O helper de finanças efectivamente importado é `applyDirection` (sinal de `amount`). T23 (formato string) eliminado.

[AUTO-DECISION A4] **Fuzzy matching de categoria por nome** — política desta story: case-insensitive substring match sobre `listCategories()`. Se "supermercado" não bate exactamente, tentar match parcial (ex: "supermercado" → "Mercearia" se `name.toLowerCase().includes(input.toLowerCase())` ou `input.toLowerCase().includes(name.toLowerCase())`). Se zero matches, retornar erro estruturado `{ success: false, error: 'Categoria não encontrada: "supermercado". Disponíveis: Mercearia, Restauração, ...' }` — sem criar transação. Se múltiplos matches, retornar o mais curto (heurística de especificidade). A 3.11 **não cria categorias novas** — usa as 10 default da Story 3.2. [GAP possível: se o utilizador pedir uma categoria totalmente fora das 10 default, a tool retorna erro — comportamento documentado no AC.]

[AUTO-DECISION A5] **Lookup de cartão por nome** — política: case-insensitive substring match sobre `listCards()` (campo `name`). Se 0 matches → erro estruturado. Se 1 match → usar. Se ≥2 matches → erro estruturado `{ success: false, error: 'Cartão ambíguo: "Millennium" corresponde a N cartões. Especifica o nome completo.' }` — nunca criar com cartão errado. Esta política garante AC de ambiguidade.

[AUTO-DECISION A6] **Direcção → sinal de `amount` via `applyDirection`** (substitui o antigo parsing de formato, redundante após decisão A3). `montante` chega já em cêntimos inteiros positivos (magnitude); o argsSchema rejeita negativos. A direcção é o campo de UX `direction: 'in'|'out'`; o execute converte para o `amount` assinado de `Transaction` chamando `applyDirection(args.montante, args.direction === 'out' ? 'saida' : 'entrada')` (`lib/financas/currencyInput.ts:97` — Edge-safe, puro). `'out'` → negativo (despesa), `'in'` → positivo (receita). Coerente com `types/db.ts:117` e o precedente da Story 3.3 (F1/F7).

[AUTO-DECISION A7] **`requiresPreview: false`** para todas as 6 tools. Padrão herdado da 2.10 — o preview é controlado pelo executor via confidence score, não por flags. Todas as tools write são reversíveis (`reversible: true`) pelo que o utilizador pode desfazer. Tools read-only: `reversible: false`, `reverse` omitido.

[AUTO-DECISION A8] **`criar_finança_variavel` usa `ctx.db.transactions.add(...)` directo** (não `createTransaction` do repo) por Edge-safety (DEV-DECISION D1 da 2.10 — repos importam singleton Dexie). Mesma decisão para as outras tools write. Dex confirma e documenta.

[AUTO-DECISION A9] **`criar_parcelada` chama `createInstallmentWithTransactions` do repo** ou replica inline. ATENÇÃO: `createInstallmentWithTransactions` usa `db.transaction('rw', ...)` atómica — se for importada no tool, puxaria Dexie para o bundle Edge (DEV-DECISION D1). Alternativa: replicar inline com `ctx.db.installments.add` + `ctx.db.transactions.bulkAdd` dentro de `ctx.db.transaction('rw', ...)`. Dex decide e documenta no Dev Agent Record. [GAP menor A-ATOMIC — verificar se `ctx.db.transaction` existe na interface `NexusDB`.]

[AUTO-DECISION A10] **`consultar_balanço` sem args → agrega todas as contas.** `accountId` opcional. Se presente, filtra. Se ausente, soma `balance` de todas as contas (positivo = crédito, negativo = débito — padrão `balanceInput.ts` da Story 3.5). Retorna `{ totalCentimos: number, formattedTotal: string, contas: ContraResumo[] }`.

[AUTO-DECISION A11] **`consultar_categoria` com `mesIso` opcional.** Se `mesIso` ausente, usa o mês corrente (`new Date().toISOString().slice(0, 7)` → `"2026-05"`). Filtra inline `ctx.db.transactions.toArray()` por **`t.category === <nome canónico>`** (string — `Transaction.category`, NÃO `categoryId`) e por `t.date` dentro do mês. Retorna `{ categoriaNome, totalCentimos, formattedTotal, count, mesIso }`.

## Acceptance Criteria

- **AC1:** **`lib/agent/tools/finance.ts`** criado com 4 tools write registadas via `toolRegistry.register(defineTool<TArgs, TResult>({...}))`:

  **`criar_finança_variavel`** (FR23 — trace: PRD §6.3, Epic 3 AC4):
  - `name: 'criar_finança_variavel'`, `domain: 'finance'`, `requiresPreview: false`, `reversible: true`
  - `argsSchema`: `CriarFinancaVariavelArgs` (montante em cêntimos inteiros — sem string, decisão PO §3/A3; direction, categoriaNome, data, descricao, cartaoNome, contaId) — conforme [A4/A5/A6]
  - `resultSchema`: `z.object({ id: z.string(), mensagem: z.string() })`
  - `execute(args, ctx)`: (1) resolve categoria via fuzzy match de `categoriaNome` sobre `ctx.db.categories.toArray()` — se não encontrar, erro estruturado PT-PT; `resolveCategoriaByNome` devolve o **`name` canónico (string)**, não um id (`Category` não tem `id` — `types/db.ts:137-142`); (2) resolve cartão por `cartaoNome` via lookup sobre `ctx.db.cards.toArray()` se `cartaoNome !== null` — se ambíguo ou não encontrado, erro estruturado; (3) calcula o `amount` **com sinal** via `applyDirection(args.montante, args.direction === 'out' ? 'saida' : 'entrada')` (helper Edge-safe de `lib/financas/currencyInput.ts` — F1/F7); (4) cria transação via `ctx.db.transactions.add({ id: crypto.randomUUID(), amount, category: <nome canónico>, description: args.descricao, date: args.data, accountId: args.contaId, cardId, recurrenceId: null, installmentId: null, createdAt: Date.now() })`. **Campos persistidos = os 10 canónicos de `Transaction` (`types/db.ts:115-126`): SEM `direction`, SEM `categoryId`, SEM `updatedAt`.** Retorna `{ id, mensagem: 'Transação de €X,XX criada na categoria Y [com cartão Z].' }` (`formatCurrency(Math.abs(amount))` para o montante na mensagem).
  - `reverse(_args, result, ctx)`: `ctx.db.transactions.delete(result.id)`.

  **`criar_finança_recorrente`** (FR23):
  - `name: 'criar_finança_recorrente'`, `domain: 'finance'`, `requiresPreview: false`, `reversible: true`
  - `argsSchema`: `CriarFinancaRecorrenteArgs`
  - `resultSchema`: `z.object({ id: z.string(), recurrenceId: z.string(), mensagem: z.string() })`
  - `execute(args, ctx)` (**F6 — sequência canónica Story 3.4, cross-link de UUIDs**):
    1. Resolve categoria (→ `category: string` canónico) + cartão (opcional → `cardId`), igual a `criar_finança_variavel`.
    2. Calcula `amount` com sinal via `applyDirection`.
    3. Gera **dois UUIDs**: `const recurrenceId = crypto.randomUUID(); const financeRecurrenceId = crypto.randomUUID();`.
    4. async function resolveCategoriaByNome(nome: string, ctx: ExecutionContext): Promise<{ id: string; name: string }> {
