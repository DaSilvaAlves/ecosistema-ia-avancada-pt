### Definição operacional de "tarefa atrasada" (FR13)

Uma tarefa é considerada **atrasada** se e só se:

```typescript
dueDate !== null
&& new Date(dueDate).getTime() < startOfToday()  // < 00:00:00 do dia actual em local time
&& status !== 'done'
```

> **Nota explícita:** "atrasada" usa `< startOfToday()` em vez de `< Date.now()`. Uma tarefa com `dueDate` igual a **hoje** não é "atrasada" — é "due today". Isto evita que toda tarefa do dia salte para a secção atrasadas às 00:00:01 de meia-noite. Trace: convenção JARVIS.txt L96 + senso comum UX para single-user pessoal.

## Decisões autónomas (River — para ratificação `@po`)

> Convenção `[AUTO-DECISION]` herdada da Story 2.2 — decisões tomadas pelo `@sm` na fase de draft que a `@po` ratifica na fase de validate. Se uma decisão for revertida, vira `Open Question` ou alteração de AC.

1. **[AUTO-DECISION D1] Drag-and-drop NÃO implementado em list view.** Trace: R1 acima. Razão: scope FR contratual prevalece sobre detalhe visual do spec. Alternativa "implementar drag em 2.3 também" foi descartada — risco de scope creep, complica testing, não está nos FRs alvo, e drag em tabela é UX duplicada do Kanban (2.4) cujo propósito é precisamente reorganização visual.

2. **[AUTO-DECISION D2] Tabs Kanban/Calendário visíveis como placeholders.** Trace: R3 acima. Razão: cria o scaffold do header uma vez, evita refactor cosmético em 2.4/2.5. Alternativa "só criar tab Lista; tabs Kanban/Calendar viriam em 2.4/2.5" foi descartada — gera commits cosmeticos a alterar layout entre stories e força utilizadores precoces (i.e., eu) a aprender duas estruturas de página.

3. **[AUTO-DECISION D3] Definição operacional de "atrasada" usa `< startOfToday()` em local time, não `< Date.now()`.** Trace: §Contexto acima. Razão: evita que uma tarefa com `dueDate` igual ao próprio dia salte para "atrasadas" às 00:00:01. Tarefa de hoje é "due today", não "overdue". UX coerente com expectativa pessoal. Alternativa `< Date.now()` foi descartada — degrada UX no início do dia.

4. **[AUTO-DECISION D4] Acções inline mínimas: marcar done (checkbox) + apagar (menu kebab).** Trace: FR9 fala de CRUD genérico mas as **acções específicas da vista lista** não são enumeradas. Razão: marcar done é a operação 10x mais frequente na vida real; apagar é segura mas potencialmente destrutiva (confirmação inline). Editar via modal aprofundado (TaskModal) **é fora-de-scope** desta story — é introduzido na story de criação UI (cf. flow 1.3 do spec). O kebab da 2.3 só faz Apagar com confirmação `confirm()` nativa; o "Editar" pode aparecer no menu mas faz `console.warn('Edição em Story 2.X')` + toast neutral. Alternativa "implementar Edit modal aqui" foi descartada — duplica scope com criação UI (story futura).
