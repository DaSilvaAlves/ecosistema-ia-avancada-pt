## User Story

**As a** `@dev` (Dex) a implementar Story 1.5 (Executor) e Story 1.8 (endpoint `/api/agent/prompt`),
**I want** uma camada `lib/agent/classifier.ts` que recebe um prompt PT-PT do utilizador, invoca `AnthropicClassifier` (Story 1.2) com system prompt few-shot bem desenhado, e devolve `ClassificationResult` com `intents` (domains da `ToolDomain` enum) e `confidence` per-intent ∈ [0, 1] validado,
**so that** o executor (Story 1.5) saiba quais tools filtrar via `toolRegistry.byDomain()` (optimização token economy arch §7.4 — executor recebe ~10 tools em vez de 39), Story 1.6 saiba quando disparar preview (confidence < 0.7), e o audit log persista os intents detectados em `AgentRun.intents`.

## Contexto

PRD §10 line 415 (Epic 1 Story 1.4): "Classifier: prompt PT-PT → intents + confidence". Architecture §8 line 682 mostra o flow: `classifier (Haiku) ──▶ { domains: ['tasks','finance'], confidence: 0.92 }`. Architecture §7.4 explicita a optimização: "classifier (Haiku) primeiro decide **domínio**, executor (Sonnet) recebe apenas tools desse domínio + tools `meta`. Assim cada chamada tem ~10 tools em vez de 39".

A Story 1.2 (Done) criou `AnthropicClassifier.classify(systemPrompt, userPrompt, opts)` que invoca o SDK Anthropic com modelo `claude-haiku-4-5-20251001` (DEFAULT_CLASSIFIER_MODEL — single source em `lib/agent/models.ts`) e devolve `ClassificationResult` validado por `ClassificationResultSchema` (`{ intents: string[], confidence: Record<string, number>, rawResponse: string, inputTokens, outputTokens }`). O **schema é canonical** — Story 1.4 não altera. A Story 1.3 (Done) criou o `ToolDomain` union (10 literais) em `lib/agent/tools/types.ts` que define os intents válidos.

A Story 1.4 fica **entre o `AnthropicClassifier` (provider abstraction) e o consumidor (Story 1.5/1.8)**. Cria:

1. **System prompt PT-PT** com few-shot examples bem desenhados (5-7 cases cobrindo single-intent, multi-intent, ambíguo low-confidence, sem domínio relevante)
2. **High-level wrapper `classifyPrompt(userPrompt, opts?)`** que injecta o system prompt, invoca o `AnthropicClassifier` via factory, valida `intents` ⊆ `ToolDomain` enum, valida `confidence ∈ [0, 1]` per-intent (validação adicional não-canonical — não altera Story 1.2 schema)

**Decisão arquitectural — `intents` = domains, não tool names:**

Architecture §6.1 line 399 mostra `AgentRun.intents: string[]` com exemplo `['criar_tarefa','criar_finança_variavel']` (tool names). Mas:
- Architecture §8 line 682 (mais recente, fluxo end-to-end) usa `domains: ['tasks','finance']`
- Architecture §7.4 (token economy) **exige** que classifier devolva domínio para filtrar tools
- Tool registry está vazio inicialmente — Story 1.4 não pode listar tool names que não existem ainda

**Resolução:** Story 1.4 fixa que `ClassificationResult.intents` contém **domains da `ToolDomain` enum** (10 literais). O exemplo `['criar_tarefa']` no JSDoc da arch §6.1 é especulativo e fica como tech debt para alinhar retrospectivamente (registar via `*backlog-add` se @architect concordar — fora do scope desta story). A Story 1.5 documenta esta decisão no executor: recebe `domains[]` do classifier, faz `toolRegistry.byDomain(d)` para cada domínio, junta com `byDomain('meta')` (cross-domain), envia tools resultantes ao Sonnet.

**Decisão arquitectural — `confidence` range:**

Architecture §8 line 682 mostra `confidence: 0.92` (single number 0..1). Story 1.2 schema canonical é `confidence: Record<string, number>` (per-intent). Story 1.4 fixa que cada `confidence[domain]` está em **[0, 1]** (probability). System prompt instrui Haiku explicitamente. O wrapper `classifyPrompt` faz check runtime adicional (lança erro PT-PT se Haiku devolver confidence < 0 ou > 1) — protege contra prompt drift sem alterar schema canonical.

Story 1.6 (Preview-then-confirm) usa o threshold `< 0.7` para disparar UI de confirmação — Story 1.4 garante confidence está calibrado para isto via prompt few-shot.

## Acceptance Criteria

- **AC1:** Existe `lib/agent/prompts/classifier-system.ts` que exporta:
  - `buildClassifierSystemPrompt(availableDomains?: ToolDomain[]): string` — devolve system prompt PT-PT formatado. `availableDomains` defaults para todos os 10 domains do `ToolDomain` enum (registry vazio em Story 1.4 — flexibilidade futura para "disable certain domains" via config). Pelo menos 5-7 few-shot examples cobrindo: 1 single-intent claro, 1 multi-intent (Epic 1 AC1 prompt), 1 ambíguo low-confidence, 1 sem domínio relevante (intents vazio), 1 meta (consulta cross-domain), 1 com vocabulário PT-BR (deve normalizar para PT-PT canonical), 1 com erro de português comum.
  - `CLASSIFIER_OUTPUT_FORMAT_RULES: string` — exportado para reuso em error messages do wrapper (e.g., "esperado: ...").

- **AC2:** Existe `lib/agent/classifier.ts` que exporta:
  - `classifyPrompt(userPrompt: string, opts?: ClassifyOpts): Promise<ClassificationResult>` — high-level wrapper
  - `interface ClassifyOpts` — `{ availableDomains?: ToolDomain[]; model?: string; maxTokens?: number; temperature?: number; }`. `model`/`maxTokens`/`temperature` são pass-through para `AnthropicClassifier.classify` (mesma forma que `ClassifierOpts` de Story 1.2). `availableDomains` é forwarded para `buildClassifierSystemPrompt`.

- **AC3:** `classifyPrompt(userPrompt, opts?)` faz:
  1. Validação de input: `userPrompt` não vazio (lança `Error('Classifier: userPrompt obrigatório')` se vazio/whitespace)
  2. Constrói system prompt via `buildClassifierSystemPrompt(opts?.availableDomains)`
  3. Invoca `getClassifier()` (factory Story 1.2) → `classify(systemPrompt, userPrompt, { model, maxTokens, temperature })`
  4. Aplica validação adicional: `intents` ⊆ `availableDomains` (ou `ToolDomain` enum se default), `confidence[d] ∈ [0, 1]` para cada `d ∈ intents`, set de keys em `confidence` ⊆ `intents`
  5. Retorna `ClassificationResult` validado

- **AC4:** Validação de output Haiku (AC3 step 4) lança erros PT-PT específicos:
  - Intent fora de `availableDomains`: `Error('Classifier: intent "${intent}" não está em availableDomains — Haiku gerou domínio inválido. rawResponse: ${rawResponse.slice(0,200)}')`
  - Confidence fora de [0, 1]: `Error('Classifier: confidence["${domain}"] = ${value} fora do range [0, 1] — prompt drift. rawResponse: ${rawResponse.slice(0,200)}')`
  - Confidence key sem intent correspondente: `Error('Classifier: confidence["${key}"] não corresponde a intent declarado. rawResponse: ${rawResponse.slice(0,200)}')`
  - Erros incluem `rawResponse` truncado (200 chars) para debug do prompt

- **AC5:** System prompt segue **estrutura mínima**:
  - **Persona:** "És o classifier do Nexus, assistente pessoal de IA do Eurico."
  - **Domains disponíveis:** lista os 10 domains (ou subset de `availableDomains`) com 1-line descrição PT-PT cada
  - **Output format:** "Responde APENAS JSON válido, sem markdown, sem prosa. Formato exacto: `{\"intents\":[\"...\"],\"confidence\":{\"...\":0.X}}`"
  - **Regras:** intents só contém domains da lista; confidence ∈ [0, 1] per-intent; multi-domínio incluir todos relevantes; ambiguous → confidence < 0.7; nada relevante → `intents: []`, `confidence: {}`
  - **Few-shot examples:** 5-7 cases conforme AC1
  - **Closing:** "Agora classifica o prompt do utilizador."

- **AC6:** Few-shot example **OBRIGATÓRIO multi-intent** que cobre o **AC1 do Epic 1** (PRD §10 line 424): prompt `"amanhã reunião 15h, paguei €78,70 supermercado"` deve produzir `{"intents":["calendar","finance"],"confidence":{"calendar":0.95,"finance":0.93}}`. Este é o benchmark central — o prompt few-shot deve ensinar o Haiku a detectar 2 domains numa única frase.

- **AC7:** Few-shot example **OBRIGATÓRIO low-confidence** para Story 1.6 (preview-then-confirm): prompt ambíguo (e.g., `"reunião amanhã ou na quarta?"`) → `{"intents":["calendar"],"confidence":{"calendar":0.55}}`. Confidence < 0.7 dispara preview.

- **AC8:** Few-shot example **OBRIGATÓRIO empty** quando prompt não corresponde a domínio relevante: prompt `"o céu é azul hoje"` → `{"intents":[],"confidence":{}}`. Lista vazia (não `['unknown']` — schema canonical aceita string[] vazio sem literal extra).

- **AC9:** **Default classifier opts**:
  - `model = DEFAULT_CLASSIFIER_MODEL` (Haiku 4.5, `lib/agent/models.ts` Story 1.2 — single source)
  - `maxTokens = 512` (suficiente para JSON de 10 domains; conservador para reduzir latência)
  - `temperature = 0` (determinismo — classifier é probabilístico mas saída deve ser estável para mesmo input)

- **AC10:** Tests Vitest + MSW em `tests/unit/agent/classifier.test.ts` cobrem:
  - **Input validation:** `classifyPrompt('')` lança erro PT-PT; `classifyPrompt('   ')` (só whitespace) lança erro

**Pattern do system prompt — design preliminar:**

```text
És o classifier do Nexus, assistente pessoal de IA do Eurico.

A tua função é analisar o prompt do utilizador (em português europeu) e
identificar QUE DOMÍNIOS funcionais devem actuar para responder.

Domínios disponíveis:
- tasks: criar/completar/listar tarefas, projectos
- finance: registar despesas, receitas, cartões, balanços
- habits: hábitos, metas, lembretes
- journal: diário, brain dumps
- knowledge: notas, áreas de conhecimento, pesquisa
- calendar: eventos, reuniões, agenda
- gmail: emails, drafts, arquivar
- telegram: enviar mensagem Telegram
- receipt: processar recibos/faturas (foto)
- meta: consultas cross-domain ("o que tenho hoje?", "balanço deste mês")

Output: APENAS JSON válido, sem markdown, sem prosa. Formato:
{"intents":["dominio_1","dominio_2"],"confidence":{"dominio_1":0.92,"dominio_2":0.85}}

Regras:
- intents só contém domínios da lista acima (lowercase, snake_case)
- confidence ∈ [0, 1] por domínio mencionado em intents
- multi-domínio: incluir todos relevantes (1+ intents)
- ambíguo: confidence < 0.7 (vai disparar preview)
- nada relevante: intents vazio []

Exemplos:

Prompt: "amanhã reunião 15h com cliente, paguei 78,70 supermercado"
Output: {"intents":["calendar","finance"],"confidence":{"calendar":0.95,"finance":0.93}}

Prompt: "criar tarefa: enviar relatório mensal"
Output: {"intents":["tasks"],"confidence":{"tasks":0.98}}

Prompt: "preciso de me lembrar de comprar pão"
Output: {"intents":["tasks"],"confidence":{"tasks":0.85}}

Prompt: "o que tenho hoje?"
Output: {"intents":["meta"],"confidence":{"meta":0.92}}

Prompt: "reunião amanhã ou na quarta?"
Output: {"intents":["calendar"],"confidence":{"calendar":0.55}}

Prompt: "vamos deletar a tarefa antiga" (PT-BR)
Output: {"intents":["tasks"],"confidence":{"tasks":0.88}}

Prompt: "o céu é azul hoje"
Output: {"intents":[],"confidence":{}}

Agora classifica o prompt do utilizador.
```

@dev pode iterar este prompt durante implementação (medir confidence calibration empiricamente). Story 1.10 (Conjunto manual de 50 prompts PT-PT) será o regression suite final.
