## Story

**As a** equipa de desenvolvimento do Nexus v2,
**I want** uma suite E2E Playwright dedicada e leve que percorra o caminho crítico completo — login → primeiro prompt → criar tarefa via UI → verificar persistência — a correr no gate CI regular (não só na suite pesada de regressão de 50 prompts),
**so that** exista uma prova automática, rápida e determinística de que o fluxo mais básico do produto (autenticar, conversar com o cérebro, ver uma tarefa nascer na UI e sobreviver a um reload) nunca regride silenciosamente, sem duplicar o esforço já investido na suite de regressão (Story 1.10/1.12) nem inflacionar o tempo do CI regular (NFR17, AC1 "tests <5 min").

**AC1 — Novo spec dedicado do caminho crítico**

Criar `tests/e2e/critical-path.spec.ts` com (pelo menos) 1 teste cobrindo, na ordem, dentro do MESMO fluxo de página (sem `beforeEach` a reconstruir estado a meio):

1. **Login** — sessão autenticada estabelecida via `loginViaApi(page)` (reutilizado de `tests/e2e/regression/helpers/auth.ts` — padrão já validado, ver Dev Notes sobre o porquê de `loginViaApi` e não `loginViaUi` aqui);
2. **Primeiro prompt** — submeter 1 prompt de chat através do `ChatComposer` real (`data-testid="chat-composer-input"`) que resulta em criação de tarefa (reutilizar o profile mock `single-task` de `mock-events.ts` — tool `criar_tarefa`);
3. **Criar tarefa via UI** — confirmar que o `ToolCard` atinge estado `success` (`[data-testid="tool-card"][data-state="success"]`) E que a tarefa criada é visível na UI de tarefas: navegar para `/tarefas` e confirmar `[data-testid="kanban-card-{id}"]` (ou, na ausência do id determinístico, pelo menos 1 card de tarefa visível a mais do que o baseline);
4. **Verificar persistência** — fazer `page.reload()` (ou nova navegação completa para `/tarefas`) e confirmar que a mesma tarefa continua visível — prova de persistência real em IndexedDB/Dexie, não apenas em estado React/Zustand em memória.
