## User Story

Como Eurico, quero o schema Dexie 4 com todas as tabelas core criado e disponível desde o início do v2, para que o @dev nunca precise de armazenar dados do Nexus em localStorage e possa crescer o schema por Epic sem surpresas de migração.

---

## Acceptance Criteria

- **AC1:** `v2/lib/db/client.ts` exporta `class NexusDB extends Dexie` e singleton `db` com schema version 1 conforme `architecture-v2.md §4.2`, com todas as tabelas: `tasks`, `projects`, `transactions`, `habits`, `habit_logs`, `goals`, `reminders`, `journal_entries`, `knowledge_areas`, `knowledge_notebooks`, `knowledge_notes`, `agent_runs`, `chat_messages`.
- **AC2:** Índices correctos para cada tabela conforme architecture §4.2 (ex: `tasks: 'id, status, projectId, dueDate, *tags, createdAt, lastWorkedAt'`).
- **AC3:** `v2/types/db.ts` exporta as interfaces TypeScript completas para todas as tabelas (Task, Project, Transaction, Account, Card, Habit, HabitLog, Goal, Reminder, JournalEntry, KnowledgeArea, KnowledgeNotebook, KnowledgeNote, AgentRun, ChatMessage, ToolCall).
- **AC4:** `v2/hooks/useDexie.ts` exporta wrapper `useLiveQuery` sobre `dexie-react-hooks` com tipos genéricos correctos.
- **AC5:** `v2/lib/db/migrations/v1-to-v2.ts` existe com função `migrateV1ToV2()` idempotente conforme `architecture-v2.md §4.4` — verifica flag `nexus_v1_migrated_to_v2` em localStorage antes de correr.
- **AC6:** `npm run typecheck` em `v2/` passa sem erros para os ficheiros de DB.
- **AC7:** Vitest unit test confirma que `db` instancia sem erros quando `fake-indexeddb` está configurado.

## Dev Notes

- **Schema exacto:** `architecture-v2.md §4.2` — snippet de código completo do `NexusDB`. Copiar exactamente, não inventar campos.
- **Interfaces:** `architecture-v2.md §6.1 a §6.5` — interfaces TypeScript por Epic; usar como fonte única de verdade para `types/db.ts`
- **Dexie versioning:** ADR-2 + `architecture-v2.md §4.2` — "schema versioning" com `this.version(1).stores({...})`. Epic 2 vai incrementar para version 2, Epic 3 para version 3, etc.
- **Migration idempotente:** `architecture-v2.md §4.4` — "uma única vez no primeiro carregamento de v2; flag `nexus_v1_migrated_to_v2` em localStorage". Se flag existe, retorna `{migrated: 0, status: 'already-done'}`.
- **fake-indexeddb para testes:** ADR-4 + `architecture-v2.md §5` — instalar `fake-indexeddb@^6.0.0`; configurar em `vitest.config.ts` globalmente
- **useDexie hook:** `architecture-v2.md §3` — `hooks/useDexie.ts` exporta `useLiveQuery` com query reactiva Dexie + React 19
- **NÃO usar localStorage para dados:** ADR-2 — localStorage só para `auth.session`, `ui.theme`, `chat.draft`. Todos os dados de negócio vão para IndexedDB via Dexie.

## Anti-padrões (explícitos para esta story)

- **NÃO** inventar tabelas ou campos fora de `architecture-v2.md §4.2` e `§6` (Constitution Article IV — No Invention)
- **NÃO** usar localStorage para armazenar tarefas, finanças, hábitos, etc. (ADR-2)
- **NÃO** usar raw IndexedDB API (ADR-2 decidiu Dexie 4 — sem `indexedDB.open()` manual)
- **NÃO** usar RxDB ou idb (ADR-2 trade-off documentado — Dexie 4 escolhido)
- **NÃO** saltar a migration v1→v2 — mesmo que Eurico não tenha dados em v1, a função deve existir para garantir smooth onboarding
- **NÃO** criar tabela `finance_entries` nem `notes` — os nomes exactos são `transactions` e `knowledge_notes` (architecture §4.2)
