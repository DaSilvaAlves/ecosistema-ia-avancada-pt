# Story 0.2 — Migrar utilities v1 para `v2/lib/` sem alterar lógica

**Story ID:** 0.2
**Epic:** 0 — Migração Estrutural
**Status:** Done
**Bloqueia:** 0.4 (layout precisa de `themes.ts`), 0.8 (widgets precisam de `usePomodoro.ts`)
**Bloqueada por:** 0.1 (estrutura `v2/` tem de existir)

---

## User Story

Como Eurico, quero que as utilities e hooks de v1 (`themes.ts`, `useLocalStorage.ts`, `usePomodoro.ts` e `lib/config.ts`) sejam portados para `v2/lib/` e `v2/hooks/`, para que o @dev tenha as bases reutilizáveis disponíveis antes de implementar o layout e os widgets.

---

## Acceptance Criteria

- **AC1:** `v2/lib/shared/themes.ts` existe com o mesmo conteúdo lógico de `src/lib/themes.ts` v1, adaptado para Next.js 15 imports (sem Vite-specifics).
- **AC2:** `v2/hooks/useLocalStorage.ts` existe com a mesma interface de `src/hooks/useLocalStorage.ts` v1.
- **AC3:** `v2/hooks/usePomodoro.ts` existe com a mesma interface de `src/hooks/usePomodoro.ts` v1, sem alterar lógica de negócio.
- **AC4:** `v2/lib/shared/format.ts` existe com formatadores PT-PT: `formatCurrency(cents: number): string` → `€1.234,56`; `formatDate(iso: string): string` → `14/03/2026`.
- **AC5:** `v2/lib/shared/env.ts` existe com validação Zod das env vars obrigatórias (arch §9.2 vars server-only) — lança erro claro se variável obrigatória falta.
- **AC6:** `v2/lib/shared/recurrence.ts` existe como wrapper sobre `rrule` (skeleton vazio para Epic 2+3+4 preencher), exporta `buildRRule(config: RecurrenceConfig): RRule`.
- **AC7:** Ficheiros de `src/` v1 estão intocados — nenhuma modificação em `imersao-tools/nexus/src/`.
- **AC8:** `npm run typecheck` em `v2/` passa sem erros para os ficheiros migrados.
