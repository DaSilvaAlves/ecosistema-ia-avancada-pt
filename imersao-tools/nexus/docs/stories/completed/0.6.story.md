# Story 0.6 — Auth flow Node runtime: bcrypt + cookie HttpOnly + session KV

**Story ID:** 0.6
**Epic:** 0 — Migração Estrutural
**Status:** Done
**Bloqueia:** 0.7 (OnboardingModal só abre após login bem sucedido)
**Bloqueada por:** 0.1 (estrutura v2)

---

## User Story

Como Eurico, quero fazer login com a minha password única, receber um cookie de sessão HttpOnly, e ser redirecionado automaticamente para a app — e ser redirecionado para `/login` se não tiver sessão activa —, para que o Nexus v2 nunca fique exposto sem autenticação.

---

## Acceptance Criteria

- **AC1:** `app/api/auth/login/route.ts` (Node runtime) aceita `POST { password }`, compara com bcrypt contra `process.env.NEXUS_PASSWORD_HASH`, e em caso de sucesso cria `sessionId` (crypto.randomUUID), grava em Vercel KV com TTL 30d, e define cookie `nexus_session=<sessionId>; HttpOnly; Secure; SameSite=Strict; Path=/`.
- **AC2:** `app/api/auth/logout/route.ts` (Node runtime) invalida o sessionId no KV e apaga o cookie.
- **AC3 (Waived 04/05/2026 by Eurico — Opção A recomendação Quinn):** `middleware.ts` (Next.js Middleware Edge runtime) interceta todos os paths excepto `api/auth/`, `_next/`, e `favicon.*`; lê cookie `nexus_session` e verifica **apenas presença** (não faz KV lookup — Edge runtime não consegue aceder KV com latência aceitável: KV REST fetch adicionaria 50-200ms ao first-byte de cada request). Se cookie ausente, redireciona para `/login`. **Defesa em camadas:** o KV lookup real ocorre nos handlers `/api/*` via `getSession()` (Node runtime), onde a auth real importa. Surface de ataque mínima: cookie inválido (sem entrada KV) só permite ver páginas estáticas; todas as operações backend (proxy Anthropic, etc.) bloqueiam via `getSession()` real.
- **AC4:** `lib/auth/session.ts` exporta `getSession(req)` que retorna `{ valid: boolean, sessionId?: string }`.
- **AC5:** `lib/auth/password.ts` exporta `verifyPassword(plain, hash)` usando `bcryptjs`.
- **AC6:** `app/(auth)/login/page.tsx` tem glass card 480px com input password + botão "Entrar"; loading state (spinner Cyan + "A validar..."); erro shake animation + texto Magenta "Password incorrecta. Verifica no Vercel." (conforme UX §1.1 steps 3-5).
- **AC7:** AC Epic 0 AC2: "Login funciona; sem cookie, redirect para login". Teste E2E Playwright confirma: (a) aceder `/` sem cookie → redirect `/login`; (b) submeter password correcta → redirect `/`.
- **AC8:** `NEXUS_PASSWORD_HASH` não aparece em nenhum ficheiro client; apenas server-side via `process.env`.

## Dev Notes

- **Runtime:** ADR-1 — `export const runtime = 'nodejs'` para auth (bcrypt usa Node crypto)
- **Auth flow exacto:** `architecture-v2.md §9.1` — snippet completo do flow login: bcrypt.compare → sessionId (crypto.randomUUID) → KV TTL 30d → Set-Cookie HttpOnly Secure SameSite=Strict
- **Middleware pattern:** `architecture-v2.md §9.1` — "Match `/(?!api/auth/|_next/|favicon).*/`; Verifica cookie → KV lookup → 200 ou redirect /login"
- **Vercel KV setup:** usar `@vercel/kv` (architecture §17). Em dev local, usar `@upstash/redis` com localhost ou variável de env `KV_URL` falsa → middleware ignora graciosamente
- **bcryptjs:** architecture §17 — `bcryptjs@^2.4.3` (não `bcrypt` nativo — evita native bindings)
- **Login UI:** `front-end-spec-v2.md §1.1` — "tela inteira fundo `#04040A`, glass card central 480px, logo NEXUS no topo; loading state: botão vira spinner Cyan + 'A validar...'; erro: shake animation + texto Magenta 'Password incorrecta. Verifica no Vercel.'"
- **KV layout:** `architecture-v2.md §9.2` — `KV_REST_API_URL` + `KV_REST_API_TOKEN` em env
- **Constraint C1:** Single-user — não há registo público, não há multi-tenant. `NEXUS_PASSWORD_HASH` é a única credencial.
- **PRD FR90-FR91:** Login por password única env-based; sem registos públicos; sem multi-utilizador.

## Anti-padrões (explícitos para esta story)

- **NÃO** usar Edge runtime neste endpoint (ADR-1 — bcrypt exige Node crypto)
- **NÃO** armazenar `NEXUS_PASSWORD_HASH` em ficheiro client (NFR5, NFR8)
- **NÃO** usar JWT sem KV lookup — sessão é stateful via KV para permitir logout imediato
- **NÃO** usar `SameSite=Lax` — deve ser `SameSite=Strict` (arch §9.1)
- **NÃO** criar segundo utilizador ou modo "convidado" (Constraint C1 — single-user)
- **NÃO** implementar magic link (PRD FR90 menciona como futuro — não MVP)
