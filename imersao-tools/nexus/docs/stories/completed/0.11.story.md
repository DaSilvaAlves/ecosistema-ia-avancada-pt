# Story 0.11 — OnboardingModal Step Google: disable temporário (F.4 follow-up)

**Estimativa:** 30min – 1h
**Tipo:** Tech Debt (Bug Fix UX)

## Contexto

A story 0.7 (Done) implementou o `OnboardingModal` com 4 steps. O Step 3 redirige para `/api/google/oauth/google` (linha 181 de `imersao-tools/nexus/v2/components/chat/OnboardingModal.tsx`) para iniciar OAuth do Google. Esse endpoint só existe a partir do Epic 6 (Google Calendar/Gmail integration) — actualmente devolve **404**.

Em produção (`https://imersao.ia.expressia.pt`, sessão 04/05/2026, primeiro login do Eurico), clicar em "Ligar Google" no Step 3 leva o utilizador a uma página `404 This page could not be found`. O botão "Saltar" funciona, mas a opção principal do step é um beco sem saída.

Esta story aplica a **Opção B** decidida no follow-up doc: desactivar temporariamente o botão "Ligar Google" com tooltip explicativo, mantendo "Saltar" como acção válida. A integração OAuth real fica para Epic 6 (ou Epic 1 conforme prioridade).

---

## User Story

Como Eurico (e qualquer membro futuro do Nexus em onboarding), quero que o passo Google do `OnboardingModal` não me leve a um 404 — em vez disso, o botão "Ligar Google" deve estar visivelmente desactivado com indicação clara de que estará disponível em breve, mantendo "Saltar" funcional, para que o primeiro contacto com o Nexus em produção transmita confiança e não quebre o fluxo de onboarding.

---

## Acceptance Criteria

- **AC1:** No `Step3` de `imersao-tools/nexus/v2/components/chat/OnboardingModal.tsx`, o botão "Ligar Google" fica permanentemente `disabled` enquanto a integração não estiver implementada (Opção B do follow-up doc).
- **AC2:** O botão "Ligar Google" desactivado mostra tooltip nativo (`title` attribute) com texto exacto: `"Disponível em breve — integração Google Calendar/Gmail a chegar."`
- **AC3:** O botão "Saltar" do Step 3 continua activo e funcional — clicar avança para Step 4 sem efeitos colaterais.
- **AC4:** A função `onConnect` que invocava `window.location.href = '/api/google/oauth/google'` deixa de ser chamada (handler removido ou neutralizado). O endpoint `/api/google/oauth/google` continua a não existir — mas nenhum click do utilizador o invoca.
- **AC5:** Visualmente, o botão desactivado segue o estado `disabled` já existente nos `PrimaryButton`/`GhostButton` (background mais ténue, cursor `not-allowed`) — usar a mesma convenção, não criar novo style.
- **AC6:** Smoke test em produção após deploy: limpar `localStorage` em `https://imersao.ia.expressia.pt`, fazer login, avançar até Step 3, clicar no botão Google → não navega; clicar Saltar → avança para Step 4.
- **AC7:** Atualizar `imersao-tools/nexus/docs/EPIC-0-FOLLOW-UP-DEBT.md` linha F.4 para indicar **Done — Opção B aplicada — {data}**, mantendo o histórico das opções.
- **AC8:** Testes unitários do `OnboardingModal` (Vitest + Testing Library) actualizados para validar que o botão "Ligar Google" está `disabled` no Step 3 e que clicar nele NÃO dispara nenhuma navegação. Testes existentes da Story 0.7 não regridem.
- **AC9:** Quality gates passam — `npm run lint`, `npm run typecheck`, `npm test`, `npm run build` na pasta `imersao-tools/nexus/v2/`.
- **AC10:** Coverage threshold actual de 25% (Story F.1 trata de subir) mantém-se PASS — esta story não tem responsabilidade de elevar coverage.
