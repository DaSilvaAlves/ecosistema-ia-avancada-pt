## User Story

Como Eurico, quero que o projecto v2 tenha o scaffold completo de testes instalado e configurado — Vitest para unit/integration, Playwright para E2E, MSW para mocks de Anthropic/Google/Telegram, e fake-indexeddb para testar código Dexie sem browser —, para que todos os epics seguintes possam escrever testes sem configuração adicional.

---

## Acceptance Criteria

- **AC1:** `npm run test:unit` dentro de `v2/` executa Vitest com jsdom, sem erros de configuração. Cria pelo menos 1 teste de smoke (`v2/tests/unit/smoke.test.ts`) que passa: `expect(1 + 1).toBe(2)`.
- **AC2:** `npm run test:e2e` dentro de `v2/` executa Playwright (Chromium) e conclui com pelo menos 1 teste de smoke (`v2/tests/e2e/smoke.spec.ts`) que verifica que `localhost:3001` retorna status 200 (ou redirige para `/login`).
- **AC3:** MSW está instalado e configurado para correr em Vitest: `v2/tests/mocks/server.ts` inicializa MSW server com `setupServer()`. Handler Anthropic (`tests/mocks/handlers/anthropic.ts`) existe com o mock multi-intent conforme `architecture-v2.md §5.2` (snippet exacto) e é importado pelo server.
- **AC4:** `fake-indexeddb` está configurado como substituto de IndexedDB em ambiente Vitest: `v2/vitest.config.ts` define `globals: true`, environment `jsdom`, e `setupFiles: ['./tests/setup.ts']`. `tests/setup.ts` importa `fake-indexeddb/auto` para substituir IndexedDB globalmente durante testes.
- **AC5:** Existe `v2/tests/unit/db/dexie-smoke.test.ts` que instancia `NexusDB` (de `lib/db/client.ts`) com fake-indexeddb, adiciona 1 tarefa, e verifica que é recuperável — sem abrir browser real.
- **AC6:** Handler MSW Google Calendar (`tests/mocks/handlers/google.ts`) e Telegram (`tests/mocks/handlers/telegram.ts`) existem como stubs vazios (sem handlers reais por enquanto — serão preenchidos nos epics respectivos).
- **AC7:** `npm run test:coverage` gera relatório de cobertura via `@vitest/coverage-v8` em `v2/coverage/`. Gate de 60% aplicado apenas a `lib/agent/`, `lib/db/`, `lib/shared/` (conforme `architecture-v2.md §5.4`) — a story 0.9 por si só não atinge os 60% (esses tests são escritos nos epics seguintes).
- **AC8:** `v2/playwright.config.ts` define `baseURL: 'http://localhost:3001'`, browser `chromium` apenas, `testDir: './tests/e2e'`, e retries 2 em CI.

## Dev Notes

- **Stack de testing:** `architecture-v2.md §5.1` — tabela completa: Vitest unit/component/integration, Playwright E2E (Chromium apenas), MSW para mocks API, fake-indexeddb para Dexie em Vitest.
- **MSW mock Anthropic:** `architecture-v2.md §5.2` — snippet exacto do handler `anthropic.ts`. Copiar literalmente — não inventar lógica alternativa.
- **fake-indexeddb:** importar via `fake-indexeddb/auto` em `setup.ts` substitui `indexedDB` global em jsdom antes dos tests. `NexusDB` instancia normalmente sem alteração.
- **Coverage gate:** `architecture-v2.md §5.4` — "Coverage gate de 60% APENAS em `lib/agent/`, `lib/db/`, `lib/shared/` — não na UI". Configurar thresholds em `vitest.config.ts` com `include` restrito a esses paths. Em story 0.9 a cobertura será baixa — os tests reais chegam nos epics.
- **Playwright config:** `architecture-v2.md §5.1` — E2E Playwright corre apenas em GitHub Actions pre-merge. Localmente `npm run test:e2e` pode ser usado mas não é obrigatório a cada commit.
- **CI:** `architecture-v2.md §13` — `npm ci --prefix v2` + `npm run lint`, `npm run typecheck`, `npm run test:unit -- --coverage`, `npx playwright install --with-deps chromium`, `npm run test:e2e`. Este scaffold é o que permite que o CI da Story 0.10 passe.
- **Porta 3001:** Playwright `baseURL` aponta para `localhost:3001` (porta do `npm run dev` do v2).
- **Retries CI:** `playwright.config.ts` — `retries: process.env.CI ? 2 : 0` para estabilidade em ambiente CI.

## Anti-padrões (explícitos para esta story)

- **NÃO** usar Jest — o projecto usa Vitest (ADR-4)
- **NÃO** usar `jest.mock()` ou imports de `jest` — usar MSW para mocks de fetch/API
- **NÃO** usar `jest-environment-jsdom` — usar `vitest` com `environment: 'jsdom'`
- **NÃO** usar Workbox — Service Worker é manual (`architecture-v2.md §11`)
- **NÃO** configurar E2E em Firefox/Safari nesta story — apenas Chromium (ADR-4: Playwright Chromium)
- **NÃO** inventar handlers MSW — seguir exactamente o snippet de `architecture-v2.md §5.2` para Anthropic
- **NÃO** tocar em `imersao-tools/nexus/src/` — v1 intocado
- **NÃO** aplicar coverage gate de 60% a componentes UI — apenas `lib/agent/`, `lib/db/`, `lib/shared/`
